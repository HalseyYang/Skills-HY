# 官方来源与证据政策

## 1. 产品事实与法规事实分开

产品事实来自用户资料；法规结论来自当次官方核验。公开同类产品可以支持比较和路径分析，但不得替代申报产品自身事实。

## 2. 来源优先级

### FDA

优先使用：

- FDA 法规和官方 guidance；
- Product Classification Database；
- 510(k)、De Novo、PMA 官方数据库及公开 summary/decision 文件；
- FDA Recognized Consensus Standards；
- FDA MDUFA fees、QMSR、eSTAR、Cybersecurity、Radiation-Emitting Products 等官方页面。

对 Predicate 或临床证据要求的判断，不得只看数据库摘要。应尽可能打开 510(k) Summary、Decision Summary、De Novo Decision Summary 或其他公开审评文件，核实该设备实际提交了哪些性能或临床证据。

### EU MDR

优先使用：

- EUR-Lex 的 Regulation (EU) 2017/745 现行文本；
- European Commission 医疗器械页面；
- MDCG 官方文件；
- NANDO；
- EUDAMED 官方页面；
- 欧盟协调标准相关官方决定/清单及标准发布方目录。

MDCG 是指导文件，应与法规原文区分。

### 标准

优先使用 ISO、IEC、CEN/CENELEC、ANSI/AAMI 等官方目录以及 FDA recognized / EU harmonised 信息。

不得把“FDA recognized”或“EU harmonised”自动写成“法规强制必须采用”。应说明该标准在项目中的作用：法规/特殊控制明确要求、认可共识标准、协调标准、常用 state-of-the-art 方法或仅作为测试参考。

## 3. 必须实时核验的事项

至少包括：

- 分类和 product code / regulation number；
- exemption 限制条件；
- 510(k)/De Novo/PMA 编号与状态；
- Predicate 是否符合 FDA 对 legally marketed predicate 的资格要求，并核查公开信息中是否存在会影响其使用的撤回/安全性状态；
- submission program 和 Third Party Review eligibility；
- FDA fee 和 small business 条件；
- QMSR / cybersecurity / eSTAR 当前状态；
- MDR 分类规则、符合性评估和过渡安排；
- NB 指定状态与 scope；
- EUDAMED / UDI 当前实施状态；
- 标准版本、撤销/替代、recognition/harmonisation；
- 第三方费率与汇率。

## 4. 证据记录

内部证据台账至少记录：

| 字段 | 内容 |
|---|---|
| Claim | 要支持的具体结论 |
| Authority | FDA / EUR-Lex / EC / NANDO / ISO 等 |
| Source | 页面或文件标题 |
| Direct link | 直达链接 |
| Version/date | 版本、发布日期或决定日期 |
| Checked on | 本次查询日期 |
| Scope | 该来源究竟支持什么 |
| Caveat | 限制条件或不能外推的内容 |

## 5. 冲突与失败处理

- 法规原文与 guidance 冲突时，法规原文优先；同时说明 guidance 的实际解释作用。
- 新旧官方页面冲突时，优先当前生效内容并记录日期。
- 同类设备证据不一致时，不做简单多数表决；分析造成差异的 intended use、technology、claim、study purpose 和审评年代。
- 官方页面不可访问或公开资料不足时，标记 `Pending`，不得用二手文章补成确定结论。
- 二手资料可用于发现候选信息，但关键结论必须回到官方来源。
