# 输入与路径决策

## 目录

1. 最小输入

4. CE MDR 决策
5. 不确定性表达

## 1. 最小输入

建立三列表：字段、内容、状态。状态仅用“已确认 / 待确认 / 研究得出”。

### 产品与用途

- 产品全称、型号和系列差异
- 预期用途、适应症、禁忌症
- 目标人群、使用者、使用场所
- 接触部位、接触时长、侵入或植入方式
- 有源、诊断、治疗、监测、测量、给药或生命支持属性
- 工作原理、关键技术和关键性能
- 软件功能、算法、网络连接、云端与移动端依赖
- 无菌、重复使用、一次性、附件和组合产品属性
- 已上市国家、已有证书、测试报告、临床和上市后数据

### 商务与交付

- 目标市场和期望路径
- 客户名称、制造商、签约主体
- 需要的服务包：分类、QMS、技术文件、CER、PMS/PMCF、Q-Sub、510(k) 等
- 各市场服务费或预算、税率、币种
- 已知第三方费用是否纳入估算
- 期望启动时间和客户内部目标

## 2. 主动提问规则

第一轮只问会改变路径、范围、周期或报价的问题，优先 5-10 个。把可从已上传资料提取的问题排除。若用户暂时无法回答，说明每个缺口可能影响的结论，并允许先输出“条件式初步方案”，但不得把条件式结论写成最终事实。

## 3. FDA 决策

1. 将预期用途、适应症、用户、场景和技术特征拆成检索词。
2. 在 FDA 官方分类数据库和相关官方页面查找可能的 regulation number、product code、class、panel、submission type 与 exemption 状态。
3. 核对产品代码详情页的限制条件和 special controls，不只看搜索摘要。
4. 查询 510(k)、De Novo 和 PMA 官方数据库中的相近设备；比较 intended use、indications、technology 和关键性能。
5. 只有在用途与技术差异可合理支持实质等同性时，才把设备列为 Predicate 候选；否则列为“参考同类设备”或建议 De Novo/PMA 进一步评估。
6. 说明 Traditional 510(k)、Special 510(k)、De Novo、PMA 或豁免结论的依据及触发条件。
7. 软件、网络安全、AI/ML、无线、无菌、生物相容性或临床数据要求必须按产品属性单独判断。

## 4. CE MDR 决策

1. 固化 intended purpose；区分诊断、监测、治疗和附件功能。
2. 确认是否属于医疗器械、附件、软件、组合产品或其他受监管类别。
3. 按 MDR Annex VIII 逐条检查适用规则，尤其是侵入性、有源、诊断/监测、软件、含药物或动物/人体组织等属性。
4. 多条规则同时适用时采用导致最高分类的规则，并解释原因。
5. 确定 Class I、Is、Im、Ir、IIa、IIb 或 III，以及 NB 是否参与。
6. 选择符合性评估路径，说明 QMS、技术文件、临床评价、PMS/PMCF、SSCP、UDI/EUDAMED 和欧代等是否适用。
7. 通过 NANDO 核验候选 NB 的 MDR 指定状态和适用产品范围；不能仅凭机构品牌或历史 CE 号判断。

## 5. 不确定性表达

使用以下句式：

- “基于目前确认的预期用途与技术特征，初步判断为……；若……，分类可能调整为……”
- “该设备可作为 Predicate 候选，但仍需完成适应症、技术特征和性能差异的逐项实质等同性评估。”
- “当前官方页面未能确认该费用/版本，暂列待核实，不纳入确定报价。”

禁止使用“肯定获批”“保证通过”“固定 X 个月拿证”等措辞。
