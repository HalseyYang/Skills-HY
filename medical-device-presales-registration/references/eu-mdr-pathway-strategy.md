# EU MDR 注册路径策略

## 1. Qualification 先于 classification

先确认产品或组件是否属于：

- medical device；
- accessory；
- medical device software；
- system/procedure pack；
- medicinal product / combination boundary；
- Annex XVI product；
- 其他法规边界类别。

不得直接从 FDA 分类映射到 MDR 分类。

## 2. Intended purpose 固化

分类前必须固化：

- medical purpose；
- diagnosis / prevention / monitoring / prediction / prognosis / treatment / alleviation 等目的；
- target population；
- anatomical site；
- user / environment；
- invasive duration；
- active / measuring / monitoring / software 属性；
- 是否控制或影响其他器械。

## 3. Annex VIII classification

逐条检查可能适用的 Annex VIII rules。多个规则同时适用时，按照 MDR 要求采用导致更高分类的规则，并说明每条规则为什么适用或不适用。

特别检查：

- invasive / surgically invasive / implantable rules；
- active therapeutic / diagnostic / monitoring rules；
- software Rule 11；
- drug delivery / medicinal substance / biological material；
- contraceptive / disinfecting / sterilizing 等特殊规则；
- Annex XVI common specifications（如适用）。

结论必须写明触发条件，例如“若增加 X 治疗用途，可能由 IIa 调整至 IIb”。

## 4. Conformity assessment

基于最终分类和产品属性，按照 Article 52 及相关 Annex 选择符合性评估路径，并说明：

- NB 是否参与；
- QMS 评审范围；
- technical documentation assessment 的方式；
- design dossier / sampling 等是否适用；
- certificate scope 与 device family 的关系。

不要把某个 Annex 写成所有同类器械唯一可选路径。

## 5. Similar Device 与 Equivalence 分级

售前阶段必须区分：

### Similar Device

用于 SOTA、benchmark、风险、临床背景和市场比较；不代表满足 MDR equivalence。

### Equivalence Candidate

仅当技术、生物学、临床特征看起来可能满足 Annex XIV 等同性标准，并且数据访问条件具有可行性时才使用该称呼。

### Equivalent Device

只有在完整完成 technical + biological + clinical equivalence demonstration 后才使用。

不得仅因为“同类 CE 产品”就称为 Equivalent Device。

## 6. Clinical evidence strategy

按 Article 61、Annex XIV 以及适用 MDCG 文件评估：

- intended purpose 和 claims；
- class / implantable status；
- state of the art；
- existing own clinical data；
- equivalent device data 的可用性和 access；
- 是否需要 clinical investigation；
- PMCF 是否可以解决 remaining uncertainty；
- Article 61 特定条款是否适用。

不得用“Class IIa/IIb 一律无需/必须临床试验”等模板化结论。

## 7. SSCP、PMS、PMCF 等

SSCP 是否适用应根据 MDR Article 32 的对象判断，不得写成“所有 IIb 必须”。

CER、PMS、PSUR、PMCF 的更新频率和要求应根据法规类别、风险、产品属性和最新 guidance 判断，不得沿用模板中的固定年度结论。

## 8. UDI / EUDAMED / SRN

根据当前实施状态和制造商角色，分别确认：

- Actor/SRN；
- Basic UDI-DI；
- UDI-DI/PI；
- device registration；
- EUDAMED 模块当前强制时间；
- PRRC；
- EU Authorized Representative（如制造商在欧盟外）。

EUDAMED 的强制日期属于动态信息，每次实时核验。

## 9. NB strategy

通过 NANDO 核验：

- NB 是否仍被指定；
- MDR scope 是否覆盖该产品类别/技术；
- 是否有额外审查能力或限制；
- 用户如需要费用或周期，再查询 NB 官方 fee schedule / quotation。

NB 排期和费用不得从历史模板直接复用。

## 10. NB pre-application clarification gate

以下情况建议在不影响 NB 独立性/公正性的前提下，提前进行 pre-application clarification 或确认其受理预期：

- qualification / classification 边界复杂；
- Annex XVI / drug-device / tissue / novel technology；
- clinical investigation 是否可豁免存在关键争议；
- equivalence access 存在疑问；
- device family / certificate scope 复杂；
- 技术标准路线与产品特性明显偏离常规。

最终输出需给出具体需要澄清的问题，而不是笼统写“建议咨询 NB”。制造商仍应对 qualification、classification 和合规策略承担责任；不要要求 NB 代替制造商设计方案或作出其不应提供的咨询性决定。
