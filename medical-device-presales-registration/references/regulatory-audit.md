# 三轮 Regulatory Audit 与终稿门槛

本文件定义内部审核。Audit 结束后直接修订正文，只输出 Final Version。

## Audit 1 — Evidence Audit

逐项检查：

- 产品关键参数是否来自用户资料，是否误用同类产品信息；
- classification、product code、rule、submission type 是否当次官方核验；
- Predicate / Reference / Similar Device 的编号和状态是否准确；
- 是否实际阅读公开 510(k)/De Novo/PMA summary，而非只看数据库标题；
- 费用、标准、NB、EUDAMED、QMSR、cybersecurity 等动态事实是否过期；
- 每个确定性法规结论是否有直接支持；
- 是否存在只靠二手来源支撑关键结论；
- 是否把 draft guidance 当成 final guidance；
- 是否把 recognized/harmonised standard 误写为绝对强制；
- 是否存在与当前结论相反的官方 precedent。

发现问题立即修订证据和正文。

## Audit 2 — Regulatory Logic Audit

从反方向重新评估，不继承第一版结论：

### FDA

- 是否存在另一 product code / regulation 更匹配；
- exemption limitation 是否改变 pathway；
- 是否真的有合法且适合的 primary predicate；
- 是否形成了 split predicate；
- 技术差异是否可能产生 new questions of safety/effectiveness；
- 临床“需要/不需要”的理由是否与实际差异和 claims 对应；
- 是否忽略 animal、human factors、software、cyber、radiation、sterility、reprocessing 等关键 evidence；
- 是否存在 De Novo/PMA 备选；
- 是否有必要 Pre-Sub。

### CE MDR

- qualification 是否先于 classification；
- 是否遗漏更高分类规则；
- conformity assessment 是否与 class/属性匹配；
- Similar Device 是否误称 Equivalent Device；
- clinical investigation / PMCF / equivalence 逻辑是否符合 Article 61 与 Annex XIV；
- SSCP、PSUR、UDI、EUDAMED、NB scope 是否适用且表述准确；
- 是否需要 NB pre-application clarification，以及该沟通是否符合 NB 独立性/公正性边界。

### 通用

- intended use/claim 是否超出支持证据；
- 多型号是否错误合并；
- 是否把历史 precedent 直接外推到当前产品；
- 是否把“可能”写成“必须”或“无需”。

发现更合理路径时必须重写主结论，不能为了维持初稿而忽略反证。

## Audit 3 — Final Consistency Audit

检查最终成稿：

- Summary 与正文路径、临床、测试、风险完全一致；
- 主路径、备选路径和触发条件没有自相矛盾；
- 时间、费用、标准、版本和查询日期一致；
- “需临床/可免临床/建议 Pre-Sub”措辞与证据强度一致；
- 客户版没有内部检索过程、内部争论或不必要的方法披露；
- 没有旧客户、旧产品、旧报价、旧税率、旧日期或模板事实残留；
- 没有“肯定获批、保证通过、固定 X 个月拿证”等承诺；
- 待确认项确实无法通过现有资料解决；
- 下一步行动明确且可执行。

## 审核后的表达规则

可以在内部记录每轮问题，但默认不输出审核清单。用户若问“是否 Audit 过”，可以回答“已完成三轮内部 Regulatory Audit 并将发现的问题回写到终稿”。

除非确实使用独立 reviewer，禁止写“独立专家已审核”。
