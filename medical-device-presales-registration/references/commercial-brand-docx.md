# 商务、品牌与 DOCX 规则

本文件在以下情形读取：

- 完整售前注册评估默认生成 Final DOCX；
- 用户要求报价；
- 用户要求品牌化 Word；
- 用户要求批注；
- 用户要求沿用现有模板。

## 1. 商务信息

只有用户要求报价或报价内容时才确认：

- 客户/制造商；
- 服务范围；
- 签约主体；
- 服务费；
- 税率和币种；
- 付款节点；
- 官方费和第三方费用是否纳入估算。

没有明确价格时不自行定价。若完整注册策略需要涉及费用边界，可将公司服务费写“待商务确认”，官方费/第三方费则按用户是否要求决定是否展开。

服务费、官方费、NB/实验室/授权代表/翻译等第三方费用必须分开。

FDA 官方费按预计递交日期所属财年实时核验；不得从历史模板复制金额。

## 2. 品牌优先级

优先级：

`用户本次明确要求 > 用户提供的最新品牌/方案文件 > 内置 clean template > 默认设计`

不得从旧方案继承客户名称、产品信息、报价、税率、日期、Predicate、标准版本、NB费率或监管结论。

## 3. 默认视觉规则

如用户没有提供更新品牌文件，使用 `assets/bioray-presales-clean-template.docx` 作为默认结构和视觉参考。具体色值和字体以用户最近确认的品牌规范为准。不要在 Skill 中把旧项目的视觉数值视为永久法规规则。

## 4. Final DOCX

完整售前评估默认生成 clean final：

- 无 QA 批注；
- 无 tracked changes；
- 无旧客户残留；
- 作者 `Hanyue Yang`；
- 清除自动备注和生成工具痕迹；
- 页码使用真实字段；
- 用户明确要求批注时才插入真实 Word comments，并按指定作者处理。

使用 `assets/bioray-presales-clean-template.docx` 时，只复用样式、页眉页脚、表格和布局，不把模板占位文本当事实。

## 5. Word 质量控制

Word 的 QA 是内部交付门槛，不是用户交付物。生成后必须：

1. 结构检查；
2. metadata / comments / tracked changes 检查；
3. render 为逐页图片；
4. 检查所有页面的字体、表格、分页、页眉页脚、Logo、遮挡和溢出；
5. 修正后重新 render；
6. 只交付最终 DOCX。
