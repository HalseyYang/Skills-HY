# HFE/UE 提交模板集（审核级）

> **用途**：2026-08-01 起 FDA 强制三层分类提交。本文件给出**类别 1/2/3 理由说明模板、URRA 审核级模板、总结性测试报告 7 节结构**——目标是 HFE 部分零 AI 请求。

---

## 1. HFE 提交类别判定理由说明模板（所有器械必交）

```
## HFE 提交类别判定说明（Decision Point A–D）

器械：[名称]  [型号]  软件版本：[X.X]
日期：[YYYY-MM-DD]  编制/审核/批准：[签字]

### Decision Point A：本提交是否属于对现有器械的修改？
结论：[是/否]
依据：[修改描述；如为 FDA 已批准器械的设计变更，引用原 K 号]

### Decision Point B：UI/用户/用途/环境/标签是否变更？
结论：[是/否]
逐项核查：
- 用户界面（UI）：[变更/未变更 + 描述]
- 用户群体：[变更/未变更 + 描述]
- 预期用途：[变更/未变更 + 描述]
- 使用环境：[变更/未变更 + 描述]
- 标签/IFU：[变更/未变更 + 描述]  ← ⚠️ IFU/标签修改也算 UI 变更（最常见误判）

### Decision Point C：是否引入新关键任务或影响现有关键任务？（基于 URRA）
结论：[是/否]
URRA 摘要：[关键任务清单编号引用；新任务/受影响任务列表]

### Decision Point D：是否必须人因验证测试？
三因素评估：
1. UI 使用历史：[有/无 + 说明]
2. 用户熟悉程度：[说明]
3. 现有风险缓解措施充分性：[说明]
结论：[必须/可不做总结性验证 + 理由]

## 最终提交类别：类别 [1/2/3]
理由综合：[一段式总结论]
```

## 2. URRA 审核级模板（扩充列）

| # | 关键任务 | 使用场景（正常/误用） | 相关危险情况 | 严重度 S | 概率 P | 风险等级 | 根因（设计/信息/环境/用户） | 现有控制措施（设计/防护/信息） | 残余风险 | 验证关联（形成性/总结性测试编号） |
|---|---------|---------------------|------------|:------:|:----:|:------:|:----------------------:|:-------------------------:|:------:|:----------------------------:|

**填写规范**：
- 危险情况从 ISO 14971 风险文件提取 + 补充纯用户操作导致的
- **根因列**是 FDA 审核员判断「设计是否可改进」的依据，不能空
- **验证关联列**：每个关键任务必须能追到形成性/总结性测试用例（没有 = 链条断）
- 判定标准：S≥3 或不可接受风险区域 → 关键任务

## 3. 总结性可用性测试报告 7 节结构（类别 3 必备，FDA 附录 A/B/C）

```
1. 概述与测试目标
   - 关键任务清单 + 每任务的成功标准
2. 参试用户
   - 每用户组 ≥15 名；代表性覆盖（医生/护士/患者/非专业）
   - 排除条件：参与过设计/形成性评估者不得参加
3. 测试环境
   - 模拟真实使用环境（手术室/急诊/家庭）+ 干扰因素
4. 测试任务与脚本
   - 覆盖 URRA 全部关键任务 + 合理可预见误用场景
   - 标准化脚本（减少主持者偏差）
5. 数据收集
   - 主指标：任务成功率；次指标：错误类型/求助频率/完成时间
   - 安全指标：使用相关危险发生次数
   - 知识任务：读 IFU 后的理解测试
6. 统计分析
   - 主判据：1-sided 95% CI 下限 ≥ 85%（每关键任务单独计算）
   - 辅助：成功率点估计、错误分布、亚组差异
7. 结论
   - 每任务达标/未达标 + 未达标处置（改设计重测，不可靠标签降级）
   - 残余使用风险可接受性结论
```

**常见报告缺陷（AI 请求来源）**：用户数不足、环境过度理想化、无知识任务、结论含糊、脚本非标准化、主持者参与过设计。

## 4. 类别 2 的理由说明要点

- 引用 Decision Point A–D 的完整结论（模板见第 1 节）
- URRA 摘要：关键任务清单 + 使用风险矩阵（不必全文）
- 形成性评估数据：**引用具体迭代与发现**（不是「做过形成性评估」一句）
- 可用性工程文件引用列表（受控编号）

## 5. 交付前 HFE 12 问

1. 类别判定按 A–D 逐条留痕了吗？
2. IFU/标签修改纳入 UI 变更评估了吗？
3. URRA 的根因列和验证关联列填了吗？
4. 每个关键任务都追到测试用例了吗？
5. 类别 3：用户数 ≥15/组？环境真实？脚本标准化？
6. 类别 3：统计判据写明 1-sided 95% CI ≥ 85%？
7. 有知识任务（IFU 理解）吗？
8. 主持者未参与设计吗？
9. 形成性评估有具体迭代记录吗？
10. 报告是 7 节完整结构吗？
11. 非专业用户产品测了 lay user 吗？
12. MDR GSPR 5 与 FDA 提交的差异说明写了吗（双市场产品）？
