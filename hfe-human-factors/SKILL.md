# FDA 人因工程合规判断器与提交方案生成器 v1.0

> **2026 关键时间线**：FDA《Content of Human Factors Information in Medical Device Marketing Submissions》终版，**2026-05-29 发布 / 2026-08-01 生效**。此后所有 510(k)/PMA/De Novo/HDE 均须按三层分类框架（类别 1/2/3）+ 决策点 A–D 提交人因资料。
>
> 💡 **决策点 D 的实操价值**：走到 D 若判定"无须人因验证测试"，可**论证免做总结性验证（summative validation）**，直接降为类别 2。口罩类（Product Code FXX）通常落入类别 1/2，常可用 D 点论证豁免。
>
> 配套指南：《Applying Human Factors and Usability Engineering to Medical Devices》为 **August 2026 版**（2026-07-22 FDA 举办 HFE Town Hall）。

## 目的

帮助医疗器械制造商判断 FDA HFE 提交类别，并生成对应的人因工程合规方案。覆盖从三层分类决策、URRA 分析、关键任务识别、形成性评估设计到总结性测试方案的全链路。

## 使用方式

### 步骤 1：判断 FDA HFE 提交类别

> 法律依据：FDA Final Guidance **"Content of Human Factors Information in Medical Device Marketing Submissions"**
> （注意官方标题是 **Submissions**，不是 Applications）
> **2026-05-29 发布 / ✅ 2026-08-01 生效**；Docket FDA-2015-D-4599，Federal Register 2026-10734（91 FR 32061）

**四步决策流程**：

```
A. 是否属于对现有器械的修改？
   → 否：新产品 → 直接进入步骤 B
   → 是：修改型提交 → 进入步骤 B

B. UI/用户/用途/环境/标签是否变更？
   → 否：类别 1（仅说明理由 + 高层级摘要）
   → 是：进入步骤 C

C. 是否引入新关键任务或影响现有关键任务？（基于 URRA）
   → 否：类别 2（理由说明 + URRA 摘要）
   → 是：进入步骤 D

D. 鉴于使用历史、界面复杂性、风险控制充分性，是否必须人因验证测试？
   → 否：类别 2（可引用形成性评估数据论证降级）
   → 是：类别 3（完整 HFE/UE 报告 + 验证测试数据）
```

**三层提交类别对照表**：

| 类别 | 触发条件 | 最低提交要求 | 典型场景 |
|------|---------|------------|---------|
| **类别 1** | UI/用户/用途/环境/标签无任何变更 | 说明理由 + 高层级摘要 | 新器械但无 UI 变更、仅内部算法修改 |
| **类别 2** | UI/标签变更但无新关键任务、不影响现有关键任务 | 理由说明（可引用形成性评估）+ URRA 摘要 | 标签文字修改、界面布局微调 |
| **类别 3** | 新关键任务或关键任务受影响，且需人因验证测试 | 完整 HFE/UE 报告 + 验证测试数据 | 新用户界面、新使用场景、新增功能 |

> ⚠️ **关键变化**：即使无关键任务，也须提交至少类别 1/2 文档。不能完全跳过 HFE 提交。

### 步骤 2：URRA 分析（Use-Related Risk Analysis）

> URRA 是 HFE 提交的基石——决定了关键任务列表和提交类别。

**URRA 工作流程**：

1. **识别使用场景**（Use Scenarios）
   - 预期用途下的正常使用场景
   - 合理可预见的误用场景（Reasonably Foreseeable Misuse）
   - 用户错误场景（User Errors）

2. **危险/危险情况识别**
   - 从 ISO 14971 风险管理文件中提取使用相关危险
   - 补充仅因用户操作导致的危险情况
   - 区分：设计固有危险 vs 使用相关危险

3. **关键任务判定**（Critical Tasks）
   > **定义**：用户操作失误可能导致重大伤害或显著降低医疗效果的交互任务

   **判定标准**：
   - 危险情况导致严重度 S ≥ 3（ISO 14971 5×5 矩阵）
   - 危险情况导致不可接受风险（🔴 矩阵区域）
   - 操作失误风险控制措施不足以将风险降至可接受水平

   **关键任务清单模板**：

| # | 关键任务 | 使用场景 | 相关危险情况 | 严重度 | 概率 | 风险等级 | 现有控制措施 | 残余风险 |
|---|---------|---------|------------|--------|------|---------|------------|---------|

4. **风险控制措施层级**（与 ISO 14971 一致）
   - 设计固有安全（最优）→ 防护措施 → 安全信息（最末）

### 步骤 3：IEC 62366-1 可用性工程流程

> 法律依据：IEC 62366-1:2015+Amd1:2020（FDA 认可共识标准 + MDR 协调标准）

**完整流程**：

```
Phase 1: 可用性工程规划
  → 制定可用性工程计划（UE Plan）
  → 定义用户群体、使用环境、用户界面要求

Phase 2: 用户界面设计与形成性评估
  → 设计用户界面（UI Design）
  → 形成性评估（Formative Evaluation）——迭代改进
  → 方法：认知走查（Cognitive Walkthrough）、模拟使用、用户访谈

Phase 3: 总结性可用性测试（HFE Validation / Summative Testing）
  → 验证关键任务的成功率
  → 评估使用相关风险的残余风险
  → 最少 15 名代表性用户（类别 3 要求）
  → 统计方法：1-sided 95% CI 下限 ≥ 85% 任务成功率

Phase 4: 可用性工程报告
  → 整合所有评估数据
  → 结论：残余使用风险是否可接受
```

### 步骤 4：人因验证测试方案（类别 3 专属）

> 类别 3 需完整人因验证测试。成本约 $50K-$200K，周期 3-6 个月。

**测试方案模板**：

#### A. 测试目标
- 验证关键任务的正确操作率
- 评估使用相关残余风险
- 确认用户界面设计是否充分控制使用风险

#### B. 参试用户
- **数量**：最少 15 名（FDA 推荐 15-25 名/用户群体）
- **代表性**：覆盖所有预期用户群体（医生/护士/技师/患者/非专业人员）
- **排除条件**：参与过产品开发或形成性评估的人员不得参与总结性测试

#### C. 测试环境
- 模拟真实使用环境（手术室/急诊室/家庭环境/现场环境）
- 必须包含预期使用环境的干扰因素
- 不应过度简化（FDA 明确禁止"实验室完美条件"）

#### D. 测试任务
- 基于 URRA 中识别的全部关键任务
- 包含正常使用和合理可预见的误用场景
- 任务脚本须标准化（减少主持者偏差）

#### E. 数据收集
- **主指标**：任务成功率（Task Success Rate）
- **次要指标**：操作错误率、错误类型、求助频率、完成时间
- **安全指标**：使用相关危险发生次数
- **知识任务**：使用说明书后的知识测试（理解关键安全信息）

#### F. 统计分析
- 1-sided 95% CI 下限 ≥ 85%（FDA 推荐基准）
- 每个关键任务单独计算成功率
- 差异分析（不同用户群体间）

#### G. 结果判定
- 所有关键任务成功率达标 → 通过
- 部分关键任务不达标 → 须修改设计后重新测试（不可仅靠标签修改降级）
- 发现非预期使用困难 → 补充形成性评估后修改设计

### 步骤 5：HFE 提交文件清单

**类别 1 提交清单**（最简）：
1. HFE 提交类别判定理由说明
2. 高层级摘要（1-2 页）

**类别 2 提交清单**（中等）：
1. HFE 提交类别判定理由说明
2. URRA 摘要（关键任务清单 + 使用风险矩阵）
3. 形成性评估数据摘要（如引用）
4. 可用性工程文件引用列表

**类别 3 提交清单**（完整）：
1. HFE 提交类别判定理由说明
2. 完整 URRA 分析报告
3. 可用性工程计划（IEC 62366-1）
4. 形成性评估报告（所有迭代）
5. 总结性可用性测试报告（HFE Validation Report）
6. 用户界面设计规范
7. 使用说明书（最终版）
8. 可用性工程总结报告（IEC 62366-1 §9.6）

### 步骤 6：与 CE MDR 的衔接

> MDR Annex I §5 + IEC 62366-1 协调标准

- **MDR 可用性要求**与 FDA HFE 要求高度趋同
- URRA 可同时满足 ISO 14971 风险管理 + IEC 62366-1 使用风险分析
- 形成性评估数据可在 FDA 和 CE 技术文件中共用
- 总结性测试方案需分别适配 FDA 和 NB 审核要求

**MDR GSPR §5 关键条款**：
- §5.1：器械设计须消除或降低使用风险
- §5.2：须考虑用户群体特征（培训/知识/体力）
- §5.3：须考虑使用环境特征

|----------|------|------|---------|

## 输出规范

- HFE 类别判定给出四步决策流程的每一步结论
- URRA 关键任务清单须覆盖所有 S≥3 使用相关危险
- 类别 3 测试方案须包含：用户数、环境、任务脚本、统计方法、判定标准
- 所有法规引用精确到条款号（如 FDA HFE Guidance §IV.B）
- 与 ISO 14971 风险管理文件的衔接点须明确标注

## 约束

- URRA 不能替代完整的 ISO 14971 风险管理——URRA 仅聚焦使用相关风险
- 类别 3 降级到类别 2 需有充分形成性评估数据论证，不可主观降级
- 总结性测试主持者不得参与产品设计（避免偏差）
- 人因测试数据必须来自代表性用户群体，不可使用公司内部员工
- 涉及 NMPA 注册时：中国可用性要求参照 YY/T 9706.106（等同 IEC 62366-1）
