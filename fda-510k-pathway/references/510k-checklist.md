## 一、完整提交文件清单（按模块）

### A. 基础行政文件（全部类型必备）

| # | 文件 | 适用类型 | 写作要点 |
|---|------|---------|---------|
| 1 | 510(k) 封面信（Cover Letter） | 全部 | 申请人信息/联络人/地址完整；eSTAR 模板在线填写（Form FDA 3514） |
| 2 | 用户费用支付凭证（MDUFA） | 全部 | **FY2026 $26,067** / 小企业 **$6,517**；⏳ **FY2027（2026-10-01 起）$28,653 / $7,163**；须提前 ≥60 天申请 SBD 认定（**小企业资格每财年重新申请，FY2026 资格 2026-09-30 失效**）；汇款后 PIN 码须嵌入 eSTAR |
| 3 | 510(k) Summary 或 Statement | 全部 | Summary 可被公众查阅；Statement 仅向 FDA 开放；按 21 CFR 807.92/93，须签字页 |
| 4 | Truthful and Accurate Statement | 全部 | 声明所有提交信息真实准确（21 CFR 807.87(k)），须签字 |
| 5 | 英文翻译完整性声明 | 全部 | 所有文件须英文或附翻译声明；外包装不得保留非英文警示语（高频拒收） |
| 6 | 第三方检测机构信息 | 全部 | 名称/地址/联系方式完整可验证；ASCA 资质须在有效期内 |

### B. 实质等同（SE）核心论证

| # | 文件 | 适用类型 | 写作要点 |
|---|------|---------|---------|
| 7 | 实质等同性论证表（12 列对比 + 差异论证） | 全部 | **核心文件**——每个差异必须论证"不影响安全有效性"；明确单一 Primary Predicate（高频拒收：列举多个 predicate 未指定 Primary） |
| 8 | 对比器械信息（Predicate） | 全部 | predicate 标签 + 510(k) Summary + K 号 + 商业名称 |

## 三、提交类型速查

| 类型 | 适用场景 | 审查周期 | 提交要点 |
|------|---------|---------|---------|
| Traditional 510(k) | 标准路径，最常用 | 90 天 | 完整提交，实质等同全论证 |
| Abbreviated 510(k) | 已遵循 FDA 认可标准 / Guidance | 90 天 | 引用标准编号，减少测试论证 |
| Special 510(k) | 已获批器械的设计变更，不影响安全有效性 | 30 天 | 变更边界清晰 |
| PCCP 510(k) 🆕 | AI/ML 器械 + PCCP 范围 | 90 天 | 三大模块 + 变更协议 |
| Third-Party 510(k) 🆕 | 部分 Class II 经认可第三方审核 | 30-60 天 | 限于认可器械清单 |

> 推荐：能走 Special 不走 Traditional；能用 Abbreviated 不浪费传统路径审查资源。

## 四、RTA 29 项拒收检查清单（高频项速记）

> 约 30% 首次提交被 RTA 退件；180 天补正期内配不齐 → 申请自动撤销，用户费不退。建议提交前对照 FDA 官方 RTA Checklist（Traditional/Abbreviated/Special 分表）逐项校验。

**最高频拒收点（务必重点核对）**
- 多个 predicate 但未指定 Primary（#6）
- 外包装保留中文警示语等翻译不完整（#8）
- 缺原材料溯源表（#12）
- 电气/电磁兼容缺 DoC（#16、#17）
- SBOM 完全缺失（#21）
- SE 对比基准不明确（#27）
- 境外临床缺认证翻译准确性证书（#28）

**其余检查项**：封面信（#1）、MDUFA 收据号（#2）、注册号一致（#3）、Form 3881（#4）、Summary/Statement（#5）、产品代码匹配（#7）、承诺书签字（#9）、第三方机构信息（#10）、器械描述对齐（#11）、生物相容性（#13）、灭菌 SAL（#14）、货架寿命（#15）、软件验证（#18、#19）、HFE 验证（#20）、漏洞管理计划（#22）、加密协议（#23）、禁忌症标注（#24）、Rx/OTC 属性（#25）、药械组合（#26）、eSTAR 导航（#29）。

## 五、HFE/UE 提交类别判定（2026 强制）

> FDA《医疗器械上市申请中人因信息内容指南》终版 2026-05-29 发布，过渡期至 **2026-08-01** 截止。制造商基于 URRA 自行判定（不再由 FDA「优先审查清单」决定）。

| 类别 | 条件 | 最低要求 |
|------|------|---------|
| 类别 1 | 无 UI 相关变更 | 说明理由 + 高层级摘要 |
| 类别 2 | 有变更但无新关键任务 | 理由说明（可引形成性评估）+ URRA 摘要 |
| 类别 3 | 新/受影响关键任务 + 需验证 | 完整 HFE/UE 报告 + 验证测试数据 |

**常见误判警示**
- IFU/标签修改也算"用户界面变更"，常被误归类别 1
- 类别 3→2 误判 → 至少追加 3-4 个月提交时间
- URRA 不完整 → FDA 可要求补充测试，补救周期 ≥3-4 个月

## 六、PCCP 三大模块（AI/ML 器械必选）

> 法律基础 FDORA 2022 §3201；指南 FDA Final Guidance 2024-12-04。

1. **Description of Modifications**：修改边界、对性能/输入/预期用途的影响、排除项
2. **Modification Protocol**：修改方法 + 验证测试、数据管理 + 模型再训练、持续监控、触发新申报的"红线"
3. **Impact Assessment**：对 SE 论证/风险-收益/标签的影响、是否更新 IFU、是否更新 510(k) Summary

---

## 七、Section 524B 网络安全章节（7 部分，网络器械必选）

> 适用范围：含软件（含固件）/ 可编程逻辑 / 可连接网络（含 USB、蓝牙、休眠无线模块）的器械。法律基础 FD&C Act §524B；指南 2025-06-27。

1. 威胁建模（STRIDE/PASS，DFD 数据流图）
2. SBOM（CycloneDX/SPDX，自动化生成）
3. Vulnerability Management Plan（VMP）
4. Coordinated Vulnerability Disclosure（CVD）
5. Security Risk Management
6. 安全测试证据（SAST/DAST/渗透/模糊）
7. 安全更新与生命周期管理

**上市后刚性时间线**：关键漏洞识别后 30 天内处理、60 天内完成补丁部署；SBOM 持续更新；鼓励提交 VEX。

## 八、UDI / GUDID 要求（境外制造商）

- Class I 与未分类器械须贴 UDI 标签 + GUDID 提交（2022-07-25 起）；可重复使用 Class I 须 Direct Marking
- GUDID 数据变更后 **30 天内**更新；不一致 → 可能被控"标识错误/掺假"
- 境外制造商须指定 US Agent 协助 GUDID 账号申请；提交方式 HL7 SPL 或 Web
- FDA Accredited Issuing Agency：GS1、HIBCC、ICCBBA、IFA

## 九、QMSR 上市后工厂检查（CP 7382.850 六大领域）

> QSIT 已废止，改为 Compliance Program 7382.850 六大领域数据流追踪。QMSR 2026-02-02 生效。

| 检查领域 | 关键 ISO 13485 条款 | 自查要点 |
|---------|-------------------|---------|
| 文件管理与质量体系 | 4.1-4.2 | 质量手册须能"讲故事"——结构、过程关联、职责清晰 |
| 生产过程控制 | 7.5 + 7.6 | 针对实际工艺参数验证（非照搬模板） |
| 供应商与采购控制 | 7.4 | 风险分级 + 量化绩效指标 |
| 上市后监督 | 8.2 | 投诉→风险→设计变更→CAPA→管理评审 全链条 |
| 纠正与预防措施 | 8.5 | CAPA 须验证有效性 |
| 术语对齐 | — | DHF→DDF、DMR→MDF；483 直接引用 ISO 13485 条款号 |

> QMSR 检查统计（MDP April 2026）：NAI 48.8% / VAI 51.2% / OAI 0.0%（vs QSIT 时期 NAI 52.7% / VAI 43.5% / OAI 3.7%）——VAI 上升，系统级缺陷发现更多。

## 十一、审查流程时间线

```
Submit → FDA 收到 → Refuse to Accept (RTA) 检查（15 天）
                         │
                    ┌─────┴─────┐
                    ▼           ▼
               通过 RTA       RTA 不通过
                    │           │ → 补充缺失文件 → 重新提交
                    ▼
              实质性审查（**90 FDA 日**为 MDUFA 决定目标；审查时钟在 AI 补充要求发出时暂停、企业答复后重启）
                    │
               ┌────┼────┐
               ▼         ▼
          AI Request  SE Letter
          (补充信息)   (实质不等同)
               │         │ → 需额外数据或换 predicate
               ▼
          审查继续
               │
               ▼
          获批 → SE (Substantially Equivalent)
```

## 十二、Predicate Device 查找策略

1. 在 FDA Product Classification Database 搜索产品代码
2. 在 FDA 510(k) Database 搜索该代码下最近获批的 510(k)
3. 优先选择近 5 年内获批的 predicate（技术更接近当代标准）
4. 查看 predicate 的 Indications for Use Statement 与 510(k) Summary
5. 如有多种选择，选技术特征最接近的，并明确指定为 Primary Predicate
6. AI 器械可额外参考 FDA AI/ML-Enabled Medical Devices List
