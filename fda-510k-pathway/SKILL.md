## 目的

帮助医疗器械制造商判断产品是否需要向 FDA 提交 510(k) 上市前通知，并规划完整的提交流程。覆盖从 predicate device 查找、提交类型选择、实质等同论证、PCCP 编写、Section 524B 网络安全章节、HFE 提交类别判定到完整文件清单的全链路。

## 快速决策流程图

```
是否需要 510(k)？
├─ 豁免（多数 Class I / 部分 Class II）→ 企业注册 + 产品列名，结束
├─ Class III → PMA 路径（非 510(k)）
└─ 需 510(k)：
    ├─ 选提交类型（Traditional / Abbreviated / Special / PCCP / Third-Party）
    ├─ 查 Predicate（明确指定 Primary）
    ├─ 填 12 列 SE 对比表（含差异论证）
    ├─ 判定 HFE 提交类别（1 / 2 / 3）
    ├─ AI 器械 → 编写 PCCP 三大模块
    ├─ 网络器械 → 编写 Section 524B 网络安全七部分
    ├─ 编完整文件清单（含 UDI / GUDID）
    └─ eSTAR **v7.0** 提交 → 29 项 RTA 自检 → 获批
       ⚠️ eSTAR v6.2 及更早（含 v6.1/v6.0）+ PreSTAR v2.2 已于 **2026-08-03 退役**，
          新提交一律用 nIVD eSTAR 7.0 / IVD eSTAR 7.0（2026-06-01 发布）；
          模板只从 FDA eSTAR 官方页下载，禁用第三方缓存版（缺板块会被退）
```

## 使用方式

### 步骤 1：判断是否需要 510(k)

先确定产品是否 510(k) 豁免：

1. 确定产品分类（Class I / II / III，参见 med-device-classifier skill）
2. 检查是否在 510(k) 豁免清单中：
   - 多数 Class I → 510(k) 豁免（除非是 reserved device）
   - 部分 Class II → 510(k) 豁免（需查 FDA 豁免清单）
   - 所有 Class III → PMA 路径（非 510(k)）
3. 未豁免的 Class I/II → 必须提交 510(k)

### 步骤 2：选择提交类型

| 类型 | 适用场景 | 审查周期 |
|------|---------|---------|
| **Traditional 510(k)** | 标准路径，最常用 | 90天 |
| **Abbreviated 510(k)** | 已遵循 FDA 认可标准/Guidance | 90天 |
| **Special 510(k)** | 已获批器械的设计变更，不影响安全有效性 | 30天 |
| **🆕 PCCP 510(k)** | AI/ML 器械 + PCCP 范围 | 90天 |
| **🆕 Third-Party 510(k)** | 部分 Class II 经认可第三方审核 | 30-60天 |

> ⚠️ **周期口径**：上表为 **FDA 日**（FDA Days），不是自然日。审查时钟在 FDA 发出补充资料要求（AI/Additional Information）时**暂停**，企业答复后重启；实际自然日通常明显长于表列值。向客户报周期时必须说明这一口径，否则极易引发预期落差。
> 📝 MDUFA VI 草案（FY2028 起）另设**平均总决策时间**口径：510(k) 平均 **128 日历日**（FY2028）→ 112 日历日（FY2032）。两个口径不可混用。

推荐：能走 Special 不走 Traditional，能用 Abbreviated 不浪费传统路径的审查资源。

### 步骤 3：查找 Predicate Device

Predicate device 是 510(k) 的核心——你需要证明你的器械与已合法上市的器械"实质等同"。

**查找工具**（按优先级）：
1. FDA 510(k) Premarket Notification Database
2. FDA Product Classification Database
3. FDA De Novo Summary Database
4. **🆕 FDA AI/ML-Enabled Medical Devices List**（AI 器械专用）

**查找策略**：
- 搜索同一 Product Code 下最近获批的 510(k)
- 优先选择近 5 年内获批的 predicate（技术更接近当代标准）
- 查看 predicate 的 Indications for Use 和 510(k) Summary

### 步骤 4：撰写实质等同论证表（12列对比表）

生成以下对比表模板：

| # | 对比要素 | Predicate Device | Your Device | 差异？ | 差异论证 |
|---|---------|-----------------|-------------|--------|---------|
| 1 | 预期用途/Indications for Use | | | | |
| 2 | 目标人群 | | | | |
| 3 | 使用环境 | | | | |
| 4 | 工作原理 | | | | |
| 5 | 材料 | | | | |
| 6 | 设计特征 | | | | |
| 7 | 性能规格 | | | | |
| 8 | 软件（如适用） | | | | |
| 9 | 灭菌方法（如适用） | | | | |
| 10 | 标签 | | | | |
| 11 | 尺寸/规格 | | | | |
| 12 | 生物相容性 | | | | |

**判定标准**：
- 差异不影响安全性和有效性 → 实质等同成立
- 差异引入了新的安全性或有效性问题 → 需要额外测试数据
- 差异改变了预期用途 → 不是同一类器械，需要换 predicate

### 步骤 5：🆕 PCCP 三大模块（AI 器械必选）

> 适用条件：AI/ML 算法的持续学习或频繁更新
> 法律基础：FDORA 2022 Section 3201
> 指南：FDA Final Guidance 2024-12-04

#### Module 1：Description of Modifications（变更描述）
- 修改的具体边界（Specific Modifications）
- 修改对性能、输入、预期用途的影响
- 排除项（不包含的修改）

#### Module 2：Modification Protocol（变更协议）
- 修改方法 + 验证测试
- 数据管理 + 模型再训练
- 持续监控
- 触发新申报的"红线"

#### Module 3：Impact Assessment（影响评估）
- 对 SE 论证、风险-收益、标签的影响
- 是否需要更新 IFU
- 是否需要更新 510(k) Summary

### 步骤 6：🆕 Section 524B 网络安全章节（联网器械必选）

> 适用范围：所有含软件（含固件）、可编程逻辑、可连接网络的器械
> 法律基础：FD&C Act Section 524B（2023 Consolidated Appropriations Act 修订）
> 指南：FDA Final Guidance **2025-06-27**（取代 2023-09 版本，官网核实 2026-07-03）

**必须包含的 7 部分**：
1. 威胁建模（Threat Model，STRIDE/PASS）
2. SBOM（Software Bill of Materials，CycloneDX/SPDX）
3. Vulnerability Management Plan
4. Coordinated Vulnerability Disclosure (CVD)
5. Security Risk Management
6. 安全测试证据（SAST/DAST/渗透/模糊）
7. 安全更新与生命周期管理

### 步骤 7：费用与时间估算

- **510(k) 用户费**（FY2026 标准，2025-10-01 至 2026-09-30）：标准 **$26,067** / 小企业 **$6,517**（须提前申请 SBD 认定）
- **审查周期**：传统 90 天，Special 30 天
- **总耗时**（含准备）：通常 6-12 个月
- **🆕 AI 器械**：PCCP 编写 + 测试，+$50K-$200K，+3-6 个月
- **🆕 网络安全**：SBOM + 渗透测试，+$30K-$80K
- **🆕 QMSR 转换**：❌ **QMSR 没有过渡期**——FDA QMSR FAQ（2026-02-02 更新）明确**自生效日即开始执法、无宽限期**，且**未发现任何正式"过渡期执法裁量"文件**。现有 QSR 820 持有者**应立即完成转换**，不存在"3 年缓冲"。
  - 检查可**回溯审查 2026-02-02 之前生成的 QMS 记录**，但记录本身**不需要改造或重新贴标**。
  - 关键动作：SOP 中失效的旧 820 子部分引用（如 820.30/820.100）须翻译为 ISO 13485:2016 条款号。
  〔2026-08-29 复审修正：原文误称"3 年过渡期（2029-02-02 截止）"，该错误同时存在于本技能合规日历、global-market-access-planner、2026-self-study-510k 及 iso13485-gap-diagnosis，已全部更正〕
- **🔍 MDUFA VI 草案关注（2026-07-08 发布，FY2028–2032）**：FDA 已发布下一轮用户费协议（MDUFA VI）草案，尚处征求意见阶段（2027-01-15 前提交国会，尚未生效）。草案含两项对中国出海企业直接相关的新动向——① 新增 **45 日「专项跟进预提交」（Tailored Review Pre-Sub）** 快速通道，复杂器械可更早锁定审查要点；② 启动 **多国同步审评试点**。⚠️ **2026-08-29 复审修正**：早期记录的「首次区分外国/本土企业注册费、外国企业费率更高」一说，在 2026-07-07 草案公开解读中未见，已从正文删除，引用前须以 FDA 最终文本为准。本技能暂不写死具体费率，建议正式申报前复核 FDA 官网最新 MDUFA VI 最终文本。

### 步骤 8：人因工程/可用性工程（HFE/UE）提交类别判定（2026年强制要求）

> ⚠️ **2026年5月29日生效**：FDA《医疗器械上市申请中人因信息内容指南》终版，过渡期至**2026年8月1日**截止。

在准备 510(k) 提交前，必须按四步决策流程判断人因资料提交层级：

**决策点**（参考 FDA 指南 Figure 1）：
1. **A** — 是否属于对现有器械的修改？
2. **B** — UI/用户/用途/环境/标签是否变更？
3. **C** — 是否引入新关键任务或影响现有关键任务？（基于 URRA 分析）
4. **D** — 鉴于使用历史、界面复杂性、风险控制充分性，是否必须 HFE 验证测试？

**三层提交类别**：

| 类别 | 条件 | 最低要求 |
|------|------|---------|
| **类别 1** | 无 UI 相关变更 | 说明理由 + 高层级摘要 |
| **类别 2** | 有变更但无新关键任务 | 理由说明（可引用形成性评估）+ URRA 摘要 |
| **类别 3** | 新/受影响关键任务 + 需验证 | 完整 HFE/UE 报告 + 验证测试数据 |

**关键变化 vs 旧规则**：
- ❌ 旧：FDA 通过「优先审查器械清单」决定谁需要 HF 数据
- ✅ 新：制造商自行基于 URRA 判断提交类别
- ❌ 旧：无关键任务的器械无需提交 HF 文档
- ✅ 新：**即使无关键任务也必须提交至少类别 1/2 文档**

**对 510(k) 提交的影响**：
- 类别 1/2：提交文件清单增加 HFE 理由说明（+1-4 周准备时间）
- 类别 3：需增加完整 HFE/UE 报告（+3-6 个月，+$50K-$200K 预算）
- 所有 510(k) 中需人因资料的申请数量将**大幅增加**

### 步骤 9：更新后的完整提交文件清单

在原有清单基础上，按类别新增人因资料：

| 原清单项 | 补充 |
|---------|------|
| 器械描述 | 增加用户界面描述（组件、交互方式） |
| 实质等同论证 | 如涉及 UI 变更 → 说明对关键任务的影响 |
| 标签 | 如标签变更 → 需附标签变更的人因影响分析 |
| **新增** | HFE/UE 提交类别判定说明（附决策流程图引用） |
| **新增**（类别 2） | URRA 摘要 + 形成性评估数据 |
| **新增**（类别 3） | 完整 HFE/UE 报告（7 节标准结构） |
| **🆕 新增** | **PCCP 三大模块**（AI 器械） |
| **🆕 新增** | **Section 524B 网络安全章节**（联网器械） |

### 步骤 10：🆕 FDA 510(k) RTA 拒收检查清单（29项行政完整性审查）

> ⚠️ **这是 FDA 的第一道门！** 约 30% 首次提交被 RTA 退件（行业经验估算），180天补正期内无法配齐 → 申请自动撤销，用户费不退还。
> 
> **来源说明**：以下29项是基于 ChinamedGlobal 深度分析归纳的行业避坑清单。FDA 官方 RTA 检查清单按 Traditional/Abbreviated/Special 三种类型分别有独立 checklist（详见 FDA Guidance for RTA Policy for 510(k)s），结构与此归纳略有差异。建议提交前务必对照 FDA 官方 checklist 原文逐项校验。

**使用 eSTAR 模板（2023年10月起强制）**：eSTAR 自带红绿灯校验机制，排除 80%+ 格式性错误。必须使用最新版本（**v6.1**，截至 2026-04），旧版本系统直接拒绝上传。自 2025-10-01 起，De Novo 申请也强制使用 eSTAR。

#### 行政性基础审查（第1-10项）

| # | RTA 检查项 | 审核标准 | 常见拒收原因 |
|---|-----------|---------|------------|
| 1 | 510(k) 封面信（申请人信息/联络人/地址） | 完整无遗漏 | 联络人邮箱格式错误 |
| 2 | MDUFA 规费收据号 | 与 eSTAR 绑定一致 | 汇款延迟72小时，PIN码未嵌入 |
| 3 | 组织机构代码及 FDA 注册号 | 填写一致 | 注册号与 FURLS 不匹配 |
| 4 | 指示性标签 Form FDA 3881 | 独立附件无格式损坏 | 扫描件模糊/低分辨率 |
| 5 | 510(k) Summary 或 Statement | 按 21 CFR 807.92/93 | 缺签字页 |
| 6 | Predicate Device K 号 + 商业名称 | 明确单一主对比器械 | ❌ **高频拒收**：列举多个 predicate 但未指定 Primary |
| 7 | 器械分类划分与产品代码 | 21 CFR Part 807 | 产品代码与分类不匹配 |
| 8 | 英文翻译完整性 | 所有文件须英文或附翻译声明 | ❌ **高频拒收**：外包装保留中文警示语 |
| 9 | 数据真实性与准确性法定承诺书 | 21 CFR 807.87(k) | 缺签字 |
| 10 | 第三方检测机构信息（名称/地址/联系方式） | 完整可验证 | ASCA 资质过期未更新 |

#### 技术性完整审查（第11-20项）

| # | RTA 检查项 | 审核标准 | 常见拒收原因 |
|---|-----------|---------|------------|
| 11 | 器械详细物理与功能描述 | 含设计图/照片 | 描述与 predicate 不对齐 |
| 12 | 材料组成（尤其接触人体材质） | 明确化学组成 | ❌ **高频拒收**：缺少原材料溯源表 |
| 13 | 生物相容性评估 | ISO 10993 核心三项（细胞毒性/致敏/皮内刺激） | 缺毒理学分析报告或豁免论证 |
| 14 | 灭菌验证（如灭菌） | SAL + 包装完整性 | 无菌保证水平不达标 |
| 15 | 货架寿命（加速/实时老化） | 含包材完整性测试 | 仅做加速未做实时 |
| 16 | 电气安全测试报告 | IEC 60601-1 合规实验室 | ❌ **高频拒收**：缺符合性声明（DoC） |
| 17 | 电磁兼容测试报告 | IEC 60601-1-2 全工作模式 | ❌ **高频拒收**：缺 DoC 或偏离说明 |
| 18 | 软件开发生命周期文件 | IEC 62304 + 版本匹配 | 软件版本与测试版本不一致 |
| 19 | 软件单元/集成/系统级验证 | 覆盖核心算法 | 仅提交测试大纲未提交完整报告 |
| 20 | HFE/UE 验证报告 | 含代表性用户试验数据 | URRA 不完整 → 3-4个月延误 |

#### 网络安全与特定设备审查（第21-29项）

| # | RTA 检查项 | 审核标准 | 常见拒收原因 |
|---|-----------|---------|------------|
| 21 | SBOM（软件物料清单） | CycloneDX/SPDX 格式 | ❌ **高频拒收**：完全缺失 |
| 22 | 漏洞管理计划（VMP） | 含定期更新维护 | 仅提交简短测试大纲 |
| 23 | 数据传输加密协议说明 | 含恶意软件防护 | 加密协议版本过旧 |
| 24 | 禁忌症/警告/预防措施说明 | 标签中明确标注 | 预防措施模糊 |
| 25 | Rx Only / OTC 监管属性标注 | 标签上清晰 | 缺标注或标注位置不规范 |
| 26 | 药械组合产品稳定度与相容性（如适用） | 含药物成分测试 | 缺药物释放速率数据 |
| 27 | SE 对比详尽对照表 | 与 predicate 技术特征逐项对比 | ❌ **高频拒收**：对比基准不明确 |
| 28 | 境外临床研究合规声明 | 赫尔辛基宣言 + GCP + 翻译准确性声明 | 缺认证翻译机构出具的准确性证书 |
| 29 | eSTAR 书签导航与目录对齐 | 文件编排统一 | 目录与书签导航不一致 |

#### RTA Hold 黄金 180 天应对法则

1. **仔细研读缺陷信** — FDA 逐条列出未通过项，附审评员意见
2. **区分缺陷类型** — 行政缺失（1天补齐）vs 技术性缺陷（需重新检测，3个月+）
3. **只给一次回复机会** — 回复仍不满足 → 直接撤销，规费不退
4. **制作缺陷对照表** — 左列复制FDA原文缺陷，中列说明修改，右列指出 eSTAR 附件名称及页码
5. **利用 eSTAR 重新打包** — 在原 PDF 中更新附件，确保顶部状态栏再次显示绿色 Complete

### 步骤 10.5：🆕 CP 7382.850 QMSR 检查六大领域（510(k) 提交后 FDA 工厂检查）

> 来源：FDA Compliance Program 7382.850（78页检查手册）+ ChinamedGlobal 深度分析

510(k) 获批后，FDA 会按 CP 7382.850 对制造商进行工厂检查。不再是 QSIT 四区抽样，而是**六大领域数据流追踪**：

| 检查领域 | 关键 ISO 13485 条款 | 2026 483 高频观察项 | 制造商自查要点 |
|---------|-------------------|-------------------|------------|
| **文件管理与质量体系** | 4.1-4.2 | 质量手册不完整 | 质量手册须能"讲故事"——结构、过程关联、职责分配清晰 |
| **🆕 FDA QMSR 检查统计** | Pre-QMSR: NAI 52.7% / VAI 43.5% / OAI 3.7% → QMSR: NAI 48.8% / VAI **51.2%** / OAI **0.0%** | VAI 大幅上升 → 检查员在新框架下发现更多系统级缺陷 | 来源：MDP April 2026 Update（deduplicated dataset） |
| **生产过程控制** | 7.5 + 7.6 | 过程验证不充分、校准记录不完整 | 针对实际工艺参数验证（非照搬模板） |
| **供应商与采购控制** | 7.4 | 供应商评价无绩效数据 | 风险分级 + 量化绩效指标 |
| **上市后监督** | 8.2 | 投诉趋势未输入管理评审 | 投诉→风险评估→设计变更→CAPA→管理评审 全链条 |
| **纠正与预防措施** | 8.5 | CAPA 未验证有效性 | "你怎么知道这个 CAPA 真的解决了问题？" |

**术语对齐（ISO 13485 语言，务必在 SOP 中更新）**：
- **DHF** → 对齐 ISO 13485 **设计开发记录**（行业简称 **DDF**，Design and Development File）⚠️ 非FDA官方术语，是ISO 13485 §7.3的术语
- **DMR** → 对齐 ISO 13485 §4.2.3 **医疗器械文档**（行业简称 **MDF**，Medical Device File）
- DHR 保留不变
- 483 现直接引用 ISO 13485 条款号（如"未按 ISO 13485:2016 §7.6 维护校准记录"），团队须熟悉 ISO 编号

**NAI 比例下降**：从 QSIT 时期 **52.7%** → QMSR 时期 **48.8%**（来源：MDP April 2026 Update）。VAI 从 43.5% → **51.2%**，OAI 从 3.7% → **0.0%**——检查员发现更多系统级缺陷，但尚未升级为执法行动。

### 补充 1：QMSR 官网 FAQ 关键细节（FDA 官网核实）

**QMSR 六个必须知道的细节**：

| # | FAQ 问题 | 官方回答要点 | 对 510(k) 的影响 |
|---|---------|------------|---------------|
| 1 | **管理评审/内审/供应商审计记录可查阅吗？** | **可以**。旧 QSR §820.180(c) 的例外不再保留，FDA 有权查阅管理评审、质量审计和供应商审计报告 | 提交前必须确保这些记录完整可追溯 |
| 2 | **QMSR 检查方式变了什么？** | QSIT（质量体系检查技术）**已废止**，新检查程序为 Compliance Program 7382.850 | FDA 检查不再按 QSIT 四区走，而是按 QMSR 全面检查 |
| 3 | **ISO 13485 标准去哪看？** | ANSI IBR Portal（https://ibr.ansi.org）可免费在线只读查看 ISO 13485:2016 和 ISO 9000:2015 Clause 3 | 编写 QMSR 对标文件时可免费引用原文 |

### 补充 2：FDA 510(k) 豁免 2026 年更新（FDA 官网核实）

> 来源：https://www.fda.gov/medical-devices/classify-your-medical-device/class-i-and-class-ii-device-exemptions + Cures Act Federal Register Notices

**2026 年 510(k) 豁免动态**：

| 日期 | 联邦公报通知 | 豁免类别 | 影响产品代码数 |
|------|-----------|---------|------------|
| 2025-06-18 | 90 FR 25889 | Class II - 临床电子体温计 | 10 |
| 2020-07-22 | 85 FR 44186 | Class II - 一般 | 5 |
| **2026-06 预期** | 新版指南《Intent to Exempt Certain Unclassified Medical Devices》 | 未分类器械 + 新增 Class II | 8类原有+5款新增（待确认） |

**510(k) 豁免通用限制条件**（21 CFR §§862.9-892.9）：
- 豁免仅适用于"现有或合理可预见特征"的器械
- 如器械用途变更、新用途、重大设计变更 → 豁免失效，必须提交 510(k)

### 补充 3：FDA 网络安全最终指南（2025-06-27 发布，2026 官网核实）

> 来源：https://www.fda.gov/medical-devices/digital-health-center-excellence/cybersecurity + Censinet 分析

**"网络器械"定义极为宽泛**：

| 判断标准 | 是否属于网络器械 |
|---------|:------------:|
| 含软件/固件 | ✅ |
| 有 Wi-Fi/蓝牙/蜂窝/感应通信 | ✅ |
| 有 USB/串口/调试端口（即使未主动联网） | ✅ |
| 休眠无线模块 | ✅ |
| 含可编程逻辑 | ✅ |

**关键：含 USB 或蓝牙的 Class I 产品也属于网络器械，须满足 Section 524B 要求**

**SPDF（安全产品开发框架）核心流程**：
1. 威胁建模（STRIDE/PASS，数据流图 DFD）
2. 网络安全风险分析（CVSS 可利用性评分 → ISO 14971 患者安全评估联动）
3. 安全架构设计（输出《安全控制目录》，每条可测试）
4. 实现阶段管控（SAST + SCA 集成 CI/CD）
5. **需求可追溯性矩阵**（风险→架构→代码→测试，SPDF 合规核心证明）

**上市后网络安全的刚性时间线**：
- 关键漏洞识别后 **30 天**内处理
- **60 天**内完成补丁部署
- 所有监测和 remediation 动作留存记录
- SBOM 必须持续更新，禁止手动编制（须自动化工具如 Syft）
- **VEX 文档鼓励提交**（说明 SBOM 中哪些漏洞实际不影响器械）

### 补充 4：FDA HFE 终版指南关键细节（FDA 官网 + ChinamedGlobal 核实）

> 来源：FDA Final Guidance 2026-05-29 + Federal Register **91 FR 2026-10734**

**决策点 D 的三个判定因素**（新增，最具影响力）：
1. 设备用户界面的使用历史（UI use history）
2. 用户对设备或类似设备的熟悉程度（user familiarity）
3. 现有风险缓解措施的充分性（adequacy of existing risk mitigations）

**常见错误警示**：
- ❌ Category 1 最常被误判：IFU/标签的修改也属于"用户界面变更"
- ❌ Category 2 与 3 的边界最易出错：低估 UI 变更对关键任务的下游影响
- ❌ 误降级代价：Category 3→2 误判 → 至少追加 **3-4 个月**提交时间
- ❌ URRA 不完整 → FDA 可要求补充测试，补救周期 **≥3-4 个月**

**HFE/UE 报告大纲变化**（vs 2016 版）：
- 第 5-6 节顺序互换：形成性评估摘要 → URRA + 关键任务识别（而非旧版反向）
- 三份新增附录：Appendix A/B/C 分别对应 Category 1/2/3 的样本报告
- 过渡期后仍用 2016 大纲 → 大概率收到 **补充信息（AI）要求**

### 补充 5：FDA UDI/GUDID 境外制造商关键要求（FDA 官网核实）

> 来源：https://www.fda.gov/medical-devices/unique-device-identification-system-udi-system/udi-rule-guidances-training-and-other-resources

**Class I 器械 UDI 合规时间线**：
- 2022-07-25 起：Class I 和未分类器械须贴 UDI 标签 + GUDID 提交
- 可重复使用 Class I 器械须直接标注（Direct Marking）
- GUDID 数据变更后 **30 天内**必须更新
- 数据不一致 → 可能被指控为"标识错误"或"掺假"

**境外制造商特别注意**：
- 须指定 US Agent 辅助 GUDID 账号申请
- GUDID 提交可通过 HL7 SPL 或 Web 界面两种方式
- FDA Accredited Issuing Agency：GS1、HIBCC、ICCBBA、IFA
