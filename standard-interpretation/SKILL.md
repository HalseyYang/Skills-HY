# 标准解读（Standard Interpretation · V3.0）

## 一、目的

将标准正文条款按「最小可执行单元」逐条拆解，严格按条款顺序输出测试用例，按「产品类别 + 测试模块」双代码体系归属，封装为 12 列固定格式 Excel 交付。

> V1.0 → V2.0 变更摘要（依据 YY 9706.262-2021 与企业 V1.1 参考版对比实证）：
> 1. 新增**四类用例形态**，修复「通用标准本章适用」「风险管理文档」「说明书/技术说明书」三类条款被系统性遗漏的问题；
> 2. 新增**验证方式标签**，承载「实测/文档审查/风险文档审查…」证据类型，**不新增列**（置于「关键词」列首位）；
> 3. 新增**拆分粒度三档**（粗/中/细），默认「中」；
> 4. 新增**规范性引用展开**可选能力，解决限值来自引用标准时的覆盖缺失；
> 5. 新增**条款号索引 + 存在性/连续性校验**，杜绝条款号笔误（如 `201.1` 误写为 `201.10`）与跳号；
> 6. 新增**规范性引用版本映射**，统一替换旧版引用；
> 7. V1.0 全部优势项原样保留（见 §二），12 列表头冻结（见 §三）。

> V2.0 → V3.0 变更摘要（针对性优化「预期结果 / 测试步骤 / 步骤参数」三项，**逻辑框架不变**）：
> 1. **预期结果分条化强制**（§四步）：多判据必须按 `1) 2) 3)` 分行分条；每条≤60 字、一句一判据；禁止把所有判据串成一段、禁止先写判据再补"符合即通过"式收尾；
> 2. **测试步骤展开引用方法**（§四步 §九）：步骤中凡出现"按 XXX 标准执行 / 按 XXX 方法"——若该方法是**本技能可复用工具库**（`references/test-method-toolkit.md`）已收录的通用方法（如 IEC/TS 62556 声功率测量、GB 9706.1 漏电流测量、GB/T 17626.x 抗扰度），**必须展开为可照做的操作序列**，不得把标准条款号当步骤；库外方法不得编造，按「简写式」保留并标注【需人工复核】；
> 3. **步骤参数显性化**（§二步 §四步）：步骤分解须"全面细致、参数清晰"——试验设备与连接、设置量值与允差、施加/持续时间、工况条件、观察与记录对象、安全防护，六要素逐项写全；参数优先落「前置条件」「测试步骤」，判据落「预期结果」；
> 4. 新增 `references/test-method-toolkit.md`（可复用试验方法展开库）与 `references/step-and-expectation-format.md`（步骤六要素 + 预期结果分条范式）；
> 5. 脚本同步新增三项软校验：预期结果分条性、步骤存在标准号残留、步骤参数完备性提示。

> V2.1 变更摘要（依据 GB 9706.224-2021 生成中断导致的"假覆盖"事故复盘）：
> 1. **条款覆盖间隙升级为真实遗漏阻断**：索引已列但未生成用例且未声明豁免的条款，生成阶段直接阻断（sys.exit），杜绝占位索引被静默放过、流出假覆盖 Excel（事故根因：中断后 202/206/208 章节仅占位无用例却照常交付）；
> 2. **新增 `_meta.exempt_clauses`**：显式声明"索引有但有意不生成用例"的条款及理由，未声明者不得凭空豁免；
> 3. **新增索引自身子条款连续性软检查**：提示 OCR 漏提导致的子条款跳号；
> 4. **新增 OCR 英文残留软告警**：用例文本列混入非白名单英文词（如 pering/probe/csv）时告警；
> 5. **新增 §0.6 引用型章节（EMC/可用性/报警）处理规范**：专标增补子条款与章内表格限值必须展开，不得整章跳过；
> 6. **长任务进度保护**：>20 条用例须分章落盘 + 断点记录 + 中断续作，禁止从头覆盖。

## 三、12 列表头冻结声明（**最高约束**）

**12 列的列名、顺序、语义固定不变，禁止增删改列。** 任何新需求必须在现有 12 列内消化：

| 新需求 | 承载方式（不得加列） |
|--------|----------------------|
| 验证方式 / 证据类型 | 「关键词」列**首位**标签（见 §九） |
| 测试的研发阶段（TR3 等） | 不落 Excel；由使用方执行台账管理 |
| 测试人员 / 结束时间 / 结果备注 | 不落 Excel；由使用方执行台账管理 |

## 四、使用时机

- 用户上传产品技术要求 / 技术指标 / 标准条款（PDF/Word/Excel），要求生成测试用例或标准符合性覆盖；
- 用户要求输出可下载的 Excel 测试用例文件（注册送检、QA 评审用）。

## 五、输入与 PDF 预检

输入：标准原文文件 + 用户指定信息（产品类别、标准号）+ **四个配置开关**（见第七步第零步）。

PDF 处理先做 30 秒文本层预检，禁止盲目处理：

1. 用 pymupdf/pdfplumber 试抽 1-2 页：> 50 字/页 → 直接抽全文；无文本层（扫描版）→ 用 Read 工具视觉识别；
2. 扫描版：先读目录页定位条款页码区间，跳过封面/前言/参考文献；同一 block 并行 3-5 页 Read；转图 1.2-1.5x 降采样；
3. 已识别标准缓存为 `cache/<标准号>.md` 复用；长文档按章节分批生成 JSON（每批 8-12 条）边生成边落盘；
4. **必做：提取条款索引**——遍历正文，收集所有出现的条款号，写入 `_meta.clause_index`，供交付前存在性与连续性校验使用。扫描版 OCR 识别不全、水印遮挡导致的条款缺失，须在【需人工复核】中标注。

## 七、执行流程（严格按序执行）

### 第零步：确认配置（动手前必做，缺项按默认值并在交付说明中标注）

| 开关 | 取值 | 默认 |
|------|------|------|
| 粒度 `granularity` | `coarse` / `medium` / `fine` | `medium` |
| 引用展开 `expand_refs` | `on` / `off` | `off`（建议注册送检场景选 `on`） |
| 全局前置条件是否成条 | `on` / `off` | `off` |
| 标准号与产品代码 | 如 `YY 9706.262-2021` / `MF` | 由用户指定 |

### 第一步：可测性门禁 + **用例形态判别**

分解任何条款前，先做两项判定。详见 `references/clause-splitting-rules.md` §0。

1. **豁免文本（0 用例）**：前言 / 引言 / 纯适用性范围描述 / 规范性引用文件清单 / 术语与定义 / 符号缩略语 / 资料性附录 / 纯原理描述段。
2. **四形态判别**（V2.0 新增，见拆分规则 §0.5）：每个条款归入且仅归入一类，据此决定成条策略——
   - **A 章级兜底**：「除下述内容外，通用标准第 X 章适用」→ **必须成 1 条**（注册送检清单须逐章声明）；
   - **B 条款本体**：条款自带可量化限值或可观察判据 → 按 §二步正常拆解；
   - **C 文档 / 记录审查**：条款明示「技术说明书应…」「用户手册应…」「应形成风险管理文档」「应讨论/应记录…」→ **清单项可按粒度拆 N 条**；
   - **D 引用标准展开**：条款指明「按某引用标准第 X 章测试」→ `expand_refs=on` 时展开子项，否则成 1 条指向性用例。
3. **准入三要素**（缺一不拆）：① 可执行动作；② 量化指标或**明确可观察判据（含文档/记录存在性与内容完备性）**；③ 合格判定准则。
   > V2.0 修订：「可观察判据」扩展覆盖**文档/记录的条目完备性**——条款明文要求「应给出/应讨论/应形成」的条目，逐条核对即为可观察判据。仍禁止对条款未写明的文档条目成条。
4. **判定对象为受试设备（EUT）**：「测设备成条，测装置/环境成条件」。
5. **环境归类**：全局通用环境 → `_meta.global_precondition`（默认不成条；`全局前置条件成条=on` 时，关键测量条件可显式成条）；条款专属条件 → 「前置条件」列。

### 第二步：最小可执行单元拆解（粒度三档）

**一个最小单元 = 一个可独立执行一次、并给出一个合格结论的试验。** 详见 `references/clause-splitting-rules.md` §1-§3。

- 按标准条款顺序逐条处理，条款号升序，禁止跳号、倒序、按分类重排；
- 拆分仅针对条款原文已写明的内容；
- **一次试验不切碎**：同一试验的多个判据、不同工况/参数设置合并为一条的检查点与步骤分支；
- **粒度三档**（作用于 C 类文档清单与并列要求）：

| 档位 | 规则 | 适用 |
|------|------|------|
| `coarse` | 每个条款 1 条，文档清单合并为 1 条 | 快速摸底、内部预审 |
| `medium`（默认） | 并列要求逐项拆，同一清单的同类项合并 | 常规用例库 |
| `fine` | 文档清单**逐项**各成 1 条（如说明书 10 项 → 10 条） | 注册送检、需逐项举证 |

- 拆分序号在「用例标题」末尾标注 `[单元 X/N]`，归属条款号填入「条款」列。

**【V3.0】拆解深度要求（"全面细致、参数清晰"）**：一个最小单元一旦确定，须把条款中**已写明的全部可执行信息**提取到用例中，不得因"条款写得简略"而输出同样简略的步骤。逐项核对下表，条款写到的必须落位，没写的不得补造：

| 信息类别 | 落位列 | 缺失处理 |
|----------|--------|----------|
| 试验设备/仪器、连接方式、夹具、探头、模拟负载 | 前置条件 / 测试步骤 | 条款未写 → 不补造 |
| 设置量值、档位、频率、功率、电平、允差 | 前置条件 / 测试步骤 | 条款写了必落位 |
| 施加时长、保持时间、循环次数、脉冲宽度 | 测试步骤 | 同上 |
| 工况/环境条件（温度、介质、耦合方式） | 前置条件（专属）/ `_meta.global_precondition`（全局） | 同上 |
| 观察对象、记录对象、数据点数量与位置 | 测试步骤 | 同上 |
| 安全防护、人员资质 | 前置条件 | 同上 |
| 量化限值、允差范围、合格边界 | 预期结果（**分条**，见第四步） | 同上 |

> 详见 `references/step-and-expectation-format.md`。

### 第三步：双代码归类与编号

产品代码（CM/RF/MF/LT/LS/PL/IPL/HA，8 项）+ 测试模块代码（AP/ST/HW/SW/PF/RL/GR/PR/FT/ESD/EMC，11 项），字典见 `references/category-code-dictionary.md`。

- **C 类文档/记录审查用例的模块归属**：说明书记载 → `AP`；技术说明书的准确性与不确定度 → `AP`；风险管理文档 → `SW` 或 `PR`（视条款所属章节）；软件资料 → `SW`。
- 用例编号：`<产品代码>-<测试模块代码>-<5 位流水号>`，全文件按条款顺序从 00001 连续编号，文件内唯一。

### 第四步：字段填写

按 12 列固定表头逐列填写，细则见 `references/column-definition.md`。要点：

- 「条款」列填原条款号，同一条款拆出的多个单元填相同条款号；
- 「关键词」列**首位必须写验证方式标签**（见 §九），其后才是关键名词，整体不超过 8 个；
- 「条款要求」列用自然语言改写实质要求，**不出现条款号、不照录原文**；
- 「前置条件」「测试步骤」「预期结果」严格取自条款原文**或其规范性引用文件**；引用展开产生的限值必须在「经验教训」列注明 `【限值来源：<引用标准号> <条款号>】`；
- 「测试结果」列留空，「结果判定」列默认 Pending。

#### 4.1 「测试步骤」列（V3.0 强化：方法必须展开、参数必须清晰）

**格式**：`1. <动作>；2. <动作>；…`，每步一个动作，顺序编号；步骤数一般 4-10 步，一条用例的全部步骤须构成闭环（能独立执行完并得出结论）。

**六要素**（条款写到的必须出现，详见 `references/step-and-expectation-format.md` §1）：

| # | 要素 | 示例写法 |
|---|------|----------|
| S1 | 试验配置与连接 | `1. 按规定连接治疗头与模拟负载，将水听器固定于声束轴线距离换能器表面 X mm 处` |
| S2 | 设备/仪器设置（含量值与允差） | `2. 设置输出功率为标称值 Po，测量仪器量程覆盖该量级，示值允差 ±5%` |
| S3 | 施加/操作动作（含参数） | `3. 连续施加输出 60 s，同时以 ≥10 Hz 采样率记录声压波形` |
| S4 | 工况切换/循环 | `4. 分别在连续与脉冲两种模式重复步骤 2-3，各测 3 次` |
| S5 | 观察与记录 | `5. 记录每次测量的声功率值及波形，计算算术平均值` |
| S6 | 异常与安全处置 | `6. 出现超温报警立即中止并记录` |

**引用方法的展开规则（V3.0 核心）**：条款写"按 XXX 标准 / XXX 方法测试"时，**禁止把标准号当步骤**，按下列两路径处理：

| 路径 | 适用 | 处理 |
|------|------|------|
| **路径 A：展开为操作序列**（优先） | 该方法已收录于 `references/test-method-toolkit.md`（IEC/TS 62556 声功率、GB 9706.1 漏电流/接地阻抗/电介质强度、GB/T 17626.2/3/4/5/6/11、GB 9706.1 环境试验等） | 用工具库中的通用操作步骤**改写成本条的具体步骤**，代入本条参数；步骤中不得出现"按 IEC/TS 62556 执行"之类指向语 |
| **路径 B：简写式 + 人工复核** | 方法未收录且无法从标准原文获取其操作细节 | 允许保留 `按 <标准号> 规定的方法`，但**必须在「经验教训」列标注** `【需人工复核：<标准号> 方法细节未展开，需查阅该标准确认操作步骤 | 来源：<标准号+条款号>】`；**禁止编造方法步骤** |

**判定**：路径 A 的步骤必须与引用标准的要求一致，不得凭常识简化（如漏电流测量须写明测量网络、施加电压、测量点、单一故障状态设置）。

#### 4.2 「预期结果」列（V3.0 强化：分条呈现、简洁清晰）

> 用户要求：**根据标准内容总结，分条呈现，语言简洁，内容清晰**——针对的正是"一大段判据揉在一起、要点看不出来"的旧版问题。

**硬性格式**：

1. **多判据必须分条**：写成 `1) …；2) …；3) …`，每条独立成行（Excel 单元格内用换行分隔），一条只讲一个判据；
2. **条目数**：2-5 条为宜；单判据条款可 1 条，但须仍是可量化判据；
3. **单条 ≤60 字**：超过即说明混装了多个判据，继续拆；
4. **句式为"主语 + 量化判据"**：
   - ✅ `1) 治疗头表面温度 ≤43 ℃；2) 超限后 2 s 内输出功率降至 0 W`
   - ❌ `设备温度应满足要求，超限时能及时停止输出，符合标准规定` （无量化、一锅端）
5. **禁止的收尾写法**：`符合要求即通过`、`各项均满足标准规定`、`无异常`——判据本身已含合格边界，不需再补收尾句；
6. **来源**：每条判据的限值必须取自条款原文或其已被展开的引用标准；引用展开的,在「经验教训」列注明【限值来源】。

> 与其他列的关系：**参数取值过程**放「测试步骤」，「合格边界」放本列；不得把测量过程写进预期结果，也不得把判据写进测试步骤。

### 第五步：复核与提示标注（只进「经验教训」列）

1. **人工复核**：`【需人工复核：<事项> | 来源：<标准号+条款号 / 知识库路径>】`；OCR 水印遮挡、扫描缺页、条款解释歧义均须标注。
2. **限值来源**（引用展开时必填）：`【限值来源：<引用标准号> <条款号>】`。
3. **产品场景提示**：`【产品场景提示：<事项>】`——企业更严限值、补充工况、历史踩坑；**不得写入判定列、不得据此生成用例**。
4. 同一条款拆出的多个单元，仅理解不清的那个单元所在行标注，不得整批标注。
5. **OCR 污染前置复查（V2.1，扫描版必做）**：JSON 落盘后、生成 Excel 前，对用例文本列（`条款要求`/`前置条件`/`测试步骤`/`预期结果`/标题）做英文残留 grep，禁止残留非白名单英文词（典型 OCR 错识：`pering`/`probe`/`csv`/`interconnect`/`Analytics` 等）；检出即修正后再生成。脚本已内置该软告警，但人工复查为第一道防线。

### 第六步：自检

按 `references/category-coverage-checklist.md` 自检，必须包含：

1. 四形态覆盖自检（ABD 是否漏 `.X 章级兜底`；C 类文档清单是否按粒度拆全）；
2. 条款号**存在性**（是否在 `_meta.clause_index` 内）与**连续性**（相对标准条款清单是否跳号、跳章）；
   2.1 **【V2.1】子条款连续性**：含个位递增子条款的章（201.12.1.101~107、x.4.4 系列）确认子条款号连续；OCR 漏提跳号须在「经验教训」列标 `【需人工复核：…】`；
3. 引用标准版本是否符合 `references/normative-ref-version-map.md`；
4. 输出顺序、判定列红线、模糊词复核；
5. **【V2.1】索引-用例一致性**：`_meta.clause_index` 每条款必须有用例或在 `_meta.exempt_clauses` 声明豁免；脚本对"真实遗漏"阻断生成，交付说明不得再把占位索引说成覆盖；
6. **【V3.0】预期结果分条自检**：多判据用例是否写成 `1) 2) 3)` 分条？是否存在单条 >60 字（判据混装）？是否存在 `符合要求即通过` 式收尾？
7. **【V3.0】步骤展开自检**：全部「测试步骤」中是否残留 `按 <标准号> 执行` 式指向语？命中的是否已在 `test-method-toolkit.md` 中（应展开）或已标【需人工复核】（可保留）？
8. **【V3.0】步骤参数自检**：对照 §二步"拆解深度要求"表，条款已写明的量值/时长/工况/观察对象是否全部落位？
9. **【V3.1】参数溯源自检（必做）**：逐条检查全部用例的每一个数值（含引用标准带来的限值）——反问"这个数字出自哪份文件的哪一条"？答不上来的**立即删除**；引用标准参数必须精确到条款号（如 `GB/T 4208 14.2.7`，不得只写标准号）；分档条件不得压缩为单值。

### 第七步：Excel 交付

1. 用 `scripts/generate_test_cases_excel.py` 生成 Excel（12 列表头冻结、首行加粗、全表筛选、「测试项目分类」「结果判定」下拉校验；脚本自动执行条款号存在性/连续性校验、旧版引用告警、**V2.1 真实遗漏阻断、子条款跳号软检查、OCR 英文残留软告警**）；
2. 文件命名：`<产品/项目简称>_测试用例_<标准号>_<YYYYMMDD>.xlsx`；
3. 通过 `present_files` 交付，并在回复中输出第六条的自检摘要；
4. **【V2.1】长任务进度保护（防中断丢章）**：标准用例 >20 条时——
   - 分章生成 JSON，每完成一章立即落盘，不攒到最后一次性写；
   - 每章完成做一次断点记录（已写到条款 X，如 `201.12.1.103`）；
   - 遇中断（频率限制/超时）恢复时，先 grep 已 `add()` 的 `clause_ref` 确认进度，再补写缺失章，**禁止从头覆盖重生成**；
   - 生成 Excel 前确认脚本未报「ERROR 条款真实遗漏」，若报则先补缺或补 `_meta.exempt_clauses`，不得带错交付。

## 九、验证方式标签（置于「关键词」列首位，**不新增列**）

| 标签 | 含义 | 典型条款 |

## 十、红线清单

- **12 列表头冻结**：禁止增删改列、禁止调整列序、禁止变更列语义（§三，最高约束）；
- **禁止扩散到产品应用**：条款未规定的场景/工况/故障模式不生成用例，产品场景仅以【产品场景提示】进「经验教训」列；
- **禁止脱离条款编造环境与判定**：限值与判据必须出自条款原文或规范性引用文件；引用展开必须在「经验教训」列注明【限值来源】，不得自行加严/放宽/补造；
- **禁止遗漏 A 类章级兜底条款**：凡出现「通用标准第 X 章适用」必须成 1 条（注册送检清单完整性要求）；
- **禁止整条丢弃 C 类文档/记录条款**：条款明示「应给出/应讨论/应形成」的须按粒度成条；仅条款确实无明确交付物时才豁免，并在交付说明中列出豁免理由；
- **禁止对文档清单"过度概括"**：`fine` 档下必须逐项成条；
- **禁止笼统合并条款**：该拆 N 条仍拆 N 条；一条用例只产生一个合格结论；
- **禁止把同一次物理试验拆成多条**；
- **禁止对试验装置/夹具/环境本身生成用例**，其内容降级为前置条件；
- **禁止按分类重新排序**，必须按条款号升序输出；
- **禁止编造标准条款内容与限值**，知识库无条款时标注【需人工复核】；
- **禁止模糊预期结果**（"符合要求""正常运行"等，脚本拦截）；
- **【V3.0】禁止预期结果"一段话一锅端"**：多判据必须分条（`1) 2) 3)`），单条 ≤60 字，一句一判据；禁止在判据后补"符合即通过"式收尾；
- **【V3.0】禁止把标准号当测试步骤**：条款写"按 XXX 标准/方法测试"时，方法已在 `references/test-method-toolkit.md` 收录的**必须展开为操作序列**；未收录的保留简写式并标【需人工复核】，**禁止编造方法步骤**；
- **【V3.0】禁止步骤参数缺失**：条款已写明的设置量值、施加时长、工况条件、观察对象必须落位到「前置条件」「测试步骤」，不得因条款表述简略而输出同样简略的步骤；
- **【V3.1】禁止凭记忆补造引用标准参数（最高优先级红线）**：写入任何引用标准的限值/条件前，**必须逐字核对原文**并标注【限值来源：<标准号> <条款号>】；无法获取原文时，只允许保留指向语 + 【需人工复核】，**禁止凭记忆/常识/通行值补数**。
  - 特别警示**概括性改写**：把分档条件压缩为单值（如 GB/T 4208 14.2.7 的"外壳高度 <850 mm → 最低点低于水面 1000 mm；≥850 mm → 最高点低于水面 150 mm"被压缩成"水面距外壳底部 ≥1000 mm"）会丢失**分档**与**部位限定**，属实质性编造；
  - 特别警示**示例数值污染**：技能/文档中用于演示的假想数值（如 `clause-splitting-rules.md` §0.4 水温案例中的 `≤5K`、`5~35℃`）**不得**当作真实标准规定引用；
  - **交付前必做自检**：逐个数值反问"这个数字出自哪份文件的哪一条"，答不上来的一律删除；
- **禁止把条款号/条款原文写进「条款要求」列**；
- **禁止把复核项/产品场景提示/限值来源写进判定列**，必须集中在「经验教训」列；
- **禁止条款号笔误与跳号**：交付前必须通过 `_meta.clause_index` 存在性与连续性校验；
- **只分解正文条款，不分解附录**：资料性附录 0 用例；规范性附录的方法仅作正文用例参考，不据附录号成条；
- **禁止对豁免文本生成用例**（术语/符号/前言/引言/范围/引用文件/纯描述段）；
- 用例编号必须严格按 `<产品代码>-<测试模块代码>-<5 位流水号>` 格式；
- 输出必须封装为 Excel 文件，不接受 Markdown 表格作为最终交付。
