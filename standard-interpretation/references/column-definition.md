# 12 列字段定义（V3.0）

本文件是 `SKILL.md` 输出列定义的详细补充，AI 在填写每条用例前必须先读本表确认列语义与边界。

> **V3.0 变更**：① 「测试步骤」列新增 **§2.2A 方法展开规范**（标准号不得当步骤）；② 「预期结果」列新增 **§2.2B 分条化规范**（多判据必须分条、单条 ≤60 字）；③ 新增 §2.2C 步骤参数完备性；④ 12 列表头继续冻结。
>
> **V2.0 变更**：① 12 列表头**冻结**，禁止增删改列；② 「关键词」列首位承载验证方式标签（§2.4）；③ 判据来源扩展至规范性引用文件（需标注【限值来源】）；④ 新增 C 类文档/记录审查用例填写细则（§2.5）。
>
> **核心红线**：用例仅由标准正文条款分解而来；「前置条件」「测试步骤」「预期结果」的环境与判据**严格取自条款原文或其规范性引用文件**，条款未写的内容不得补造；产品场景、实验室惯例只进「经验教训」列（见 §2.3）。

## §1 主体 12 列

| # | 列名 | 数据类型 | 填写规范 | 数据校验 |
|---|------|----------|----------|----------|
| 1 | 用例编号 | 字符串 | `<产品代码>-<测试模块代码>-<5 位流水号>`，全大写、半角连字符 | 正则：`^[A-Z]{2,3}-[A-Z]{2,4}-\d{5}$` |
| 2 | 测试项目分类 | 字符串 | `<产品代码>-<测试模块代码> <测试模块名称>` | 数据校验下拉，引用字典 sheet |
| 3 | 关键词 | 字符串 | **首位为验证方式标签**，其余为关键名词/动作；逗号分隔，最多 8 个 | 非空，首位须命中标签字典（见 §2.4），禁止"测试/验证"等无信息量词 |
| 4 | 条款 | 字符串 | 该用例归属的原条款号（正文数字条款号，如 `201.12.4.4.101`；禁止填附录编号） | 非空，符合条款号格式 |
| 5 | 用例标题 | 字符串 | 动词短语，< 30 字；末尾可用 `[单元 1/N]` 标注拆分序号 | 非空 |
| 6 | 条款要求 | 字符串 | 自然语言描述实质要求（不出现条款号、不照录原文） | 非空 |
| 7 | 前置条件 | 字符串 | 条款专属特殊试验条件，**严格取自条款原文**（全局通用环境不填本列，见 §3A） | 非空 |
| 8 | 测试步骤 | 字符串 | 顺序编号，每步一个动作；**引用方法展开为操作序列**，参数写全（见 §2.2A、§2.2C） | 非空 |
| 9 | 预期结果 | 字符串 | **分条呈现**（`1) 2) 3)`），每条 ≤60 字、一判据，可量化可判定（见 §2.2B） | 非空，禁止"符合要求/正常运行/无异常" |
| 10 | 经验教训 | 字符串 | 留空 / 【需人工复核：…】/ 【产品场景提示：…】 | 无（执行后可补充） |
| 11 | 测试结果 | 字符串 | 留空/实际测量值或现象 | 无（执行后填写） |
| 12 | 结果判定 | 枚举 | Pass/Fail/Blocked/N/A/Pending | 数据校验下拉 |

## §2 关键列语义边界

### 2.1 「条款」列

- 填的是**原条款号**（字符串），不是数字；禁止填附录编号；
- 同一条原条款拆出的 N 个最小单元，每行都填同一个原条款号；
- 拆分序号体现在「用例标题」末尾 `[单元 X/N]`；
- JSON 字段名统一为 `clause_ref`。

### 2.2 「条款要求」列

- 禁止出现条款号（如 201.4.3.101、§4.3、条款 a)）；
- 禁止照录条款原文；
- 用改写后的自然语言描述本条用例要验证的实质要求，看上去就像一段简明的测试任务说明；
- 示例：
  - 错：`201.4.3.101.1 a) 应没有与所实施治疗相关的错误数值的显示。`
  - 对：`设备治疗过程显示的所有数值必须与所实施治疗的实际参数一致，不得出现与治疗无关或错误的数值显示。`

### 2.2A 「测试步骤」列：引用方法必须展开（V3.0 新增·核心）

**问题**：旧版步骤常写成 `1. 按 IEC/TS 62556 规定的方法测量声功率`——把标准号当步骤，执行者仍需自行查标准，用例不可照做。

**规则**：

1. 步骤中原则上**不得出现标准号**（例外见第 3 条）；
2. 条款指明"按某引用标准测试"时，若该方法已收录于 `references/test-method-toolkit.md` → **路径 A：用工具库的通用操作序列改写成步骤**，代入本条具体参数；
3. 库外方法且无法从原文获得操作细节 → **路径 B**：允许保留 `按 <标准号> 规定的方法`，但必须在「经验教训」列标注
   `【需人工复核：<标准号> 方法细节未展开，需查阅该标准确认操作步骤 | 来源：<标准号+条款号>】`；
4. **禁止编造方法步骤**；不确定时走路径 B。

**正反例**：

| 场景 | ❌ 错误（标准号当步骤） | ✅ 正确（展开为操作序列） |
|------|------------------------|--------------------------|
| 声功率测量（条款指明按 IEC/TS 62556） | `1. 按 IEC/TS 62556 测量声功率；2. 与标称值比较` | `1. 将水听器固定于声束轴线距换能器表面 5 mm 处；2. 设置输出功率为标称值，连续输出 60 s；3. 以 ≥10 Hz 采样率记录声压波形并计算声功率；4. 重复 3 次取算术平均` |
| 漏电流测量（条款指明按 GB 9706.1 第 8 章） | `1. 按 GB 9706.1 测漏电流` | `1. 按规定接入测量网络（1 kΩ 无感电阻并联 0.015 µF 电容）；2. 施加 1.1 倍额定电压的 110% 于相应端子；3. 分别测量外壳漏电流、患者漏电流；4. 逐一设置单一故障状态并复测` |

### 2.2B 「预期结果」列：分条化（V3.0 新增·核心）

> 用户诉求："根据标准文件内容进行总结，通过分条呈现，语言简洁，内容清晰"。

**硬性格式**：

1. **多判据必须分条**：`1) …；2) …；3) …`，每条独立成行（单元格内换行）；
2. **一条只讲一个判据**；条目数 2-5 条；单判据条款可 1 条；
3. **单条 ≤60 字**，超出即继续拆；
4. **句式 = 主语 + 量化判据**（数值 + 单位 + 合格边界）；
5. **禁止收尾语**：`符合要求即通过`、`各项均满足标准规定`、`无异常`；
6. 限值来源须为条款原文或已展开的引用标准（后者在「经验教训」列标【限值来源】）。

**正反例**：

| ❌ 错误 | ✅ 正确 |
|---------|---------|
| `治疗头温度应符合标准要求，超温时应能及时停止输出，设备无异常，符合要求即通过` | `1) 治疗头表面温度 ≤43 ℃；2) 温度超限后 2 s 内输出功率降至 0 W；3) 同时发出声光报警` |
| `说明书应齐全并满足要求` | `说明书应包含下列条目且内容完整：1) 超声治疗禁忌症清单；2) 电气安装建议；3) B 型应用部分危害提醒。缺任一项即判不符合` |
| `漏电流在允许范围内` | `1) 外壳漏电流 ≤100 µA（正常状态）；2) 患者漏电流 ≤100 µA（正常状态）；3) 单一故障状态下均 ≤500 µA` |

### 2.2C 「测试步骤」列：参数完备性（V3.0 新增）

条款**已写明**的下列信息必须落位（条款未写的不补造）：

| 信息类别 | 落位列 |
|----------|--------|
| 试验设备/仪器、连接方式、夹具、探头、模拟负载 | 前置条件 或 测试步骤 |
| 设置量值、档位、频率、功率、电平、允差 | 前置条件 或 测试步骤 |
| 施加时长、保持时间、循环次数、脉冲宽度 | 测试步骤 |
| 工况/环境条件 | 前置条件（专属）/ `_meta.global_precondition`（全局） |
| 观察对象、记录对象、数据点数量与位置 | 测试步骤 |
| 安全防护、人员资质 | 前置条件 |
| 量化限值、允差、合格边界 | **预期结果（分条）** |

> 详细步骤范式见 `references/step-and-expectation-format.md`。

### 2.3 「经验教训」列

承载 4 类内容（**唯一允许承载产品视角内容的列**）：

1. **人工复核标注**：`【需人工复核：<事项> | 来源：<标准号+条款号 / 知识库路径>】`；
2. **产品场景提示**：`【产品场景提示：<事项>】`——企业更严限值、产品需补充的工况/联锁场景、实验室惯例（非标准原文要求时必须注明"非标准原文要求"）；
3. **踩坑要点**（历史测试中的注意事项、风险点）；
4. 与其他正文条款的关联引用。

> 示例（水温红线）：条款只写"水温与试样温差 ≤5K"，实验室惯例 5~35℃ 不得写进前置条件，只可写：
> `【产品场景提示：实验室环境试验通用条件 5~35℃，非标准原文强制要求，仅供执行参考】`
>
> ⚠️ 本示例中的数值为**示范用**（`≤5K` 句式取自 GB/T 4208 14.2.7 d)），**不得**据以在用例中直接引用；引用具体数值须回到对应标准原文并标注【限值来源】。

**禁止**：把上述任何内容写进「条款要求」「前置条件」「测试步骤」「预期结果」四个判定列。

### 2.3A 「经验教训」列承载内容清单（V2.0 增补为 5 类）

1. `【需人工复核：<事项> | 来源：<标准号+条款号 / 知识库路径>】`
2. `【限值来源：<引用标准号> <条款号>】`——**D 类引用展开用例必填**；
3. `【产品场景提示：<事项>】`
4. 踩坑要点（历史测试注意事项、风险点）；
5. 与其他正文条款的关联引用。

## §2.4 验证方式标签（「关键词」列首位，**不新增列**）

12 列表头冻结，证据类型通过「关键词」列首位标签承载，以实现按证据来源筛选与分工派工。

**格式**：`<验证方式>,<关键名词1>,<关键名词2>…`（首位必须是标签，其后 ≤7 个关键词）

| 标签 | 含义 | 典型条款 |
|------|------|----------|
| `实测` | 仪器测量 / 环境试验 / 通电操作 | 201.10.102、202.6.2.3 |
| `目击检查` | 外观、标识、显示可读性现场目测 | 201.7.4.101 |
| `文档审查` | 核对使用说明书 / 技术说明书条目完备性 | 201.7.9.2.1、201.12.1.103 |
| `风险文档审查` | 核对风险管理文档条目完备性 | 201.10.103、201.13 |
| `软件资料审查` | 核对软件生存周期 / PEMS 文档 | 201.14 |
| `引用` | 指向引用标准章节（A 类章级兜底） | 201.4、201.5、201.8 |

> 示例：`文档审查,使用说明书,禁忌症,电气安装,电位均衡`
> 示例：`引用,通用要求,通标第4章`

## §2.5 C 类「文档/记录审查」用例填写细则

- **前置条件**：写明受审文档名称与版本，如「已形成最终版使用说明书」；无专属条件时填文档类型即可（**禁止留空或填 `/`**）；
- **测试步骤**：逐条列出核对动作，如「检查使用说明书是否提供超声治疗禁忌症清单」；
- **预期结果**：必须可判定，写成「使用说明书应提供下列条目且内容完整：<条目清单>；缺项即判不符合」——**禁止**写成"文档齐全""满足要求"；
- **经验教训**：清单来自条款但未定量时，标注 `【需人工复核：<条目>的具体数值/深度由企业技术要求确定 | 来源：<标准号+条款号>】`。

## §3A 全局前置条件（不落 Excel、仅记录留存）

全局通用测试环境**不生成独立用例、不占用第 7 列主体**。处理规则：

- **识别范围**：标准原文规定的温湿度、大气压、电网/电源条件、通用测量仪器、人员资质、通用安全防护等，且多数条款共用者；**内容必须出自标准原文，不得补造条款未写的环境区间**；
- **存放位置**：JSON 顶层 `_meta.global_precondition`（仅记录留存，Excel 不渲染）；
- **挂载语义**：该标准下全部用例默认继承复用，无需逐条复制；
- **第 7 列职责**：只填条款专属特殊试验条件；无专属条件时填「同【全局前置条件】」或该条设备初始状态。

## §4 数据校验下拉值

### 4.1 测试项目分类下拉（引用字典 sheet）

字典 sheet 由 `scripts/init_workbook.py` 自动生成，两列：`<产品代码>-<测试模块代码>`、`<产品代码>-<测试模块代码> <测试模块名称>`，共 88 项笛卡尔积，见 `category-code-dictionary.md`。

### 4.2 结果判定下拉

- Pass：通过
- Fail：不通过
- Blocked：阻塞
- N/A：不适用
- Pending：待定（必须在「经验教训」列说明原因）

## §5 Excel 样式规范

1. 表头行高 28，加粗、底色 #4472C4（深蓝）配白字、水平居中、垂直居中、自动换行；
2. 用例编号：等宽字体（Consolas）；
3. 关键列（条款要求/前置条件/测试步骤/预期结果/经验教训）启用自动换行；
4. 冻结首行（表头下方第 1 行）；数据区按列启用筛选；
5. 列宽建议（字符数）：用例编号 16 / 测试项目分类 22 / 关键词 20 / 条款 16 / 用例标题 32 / 条款要求 46 / 前置条件 28 / 测试步骤 46 / 预期结果 36 / 经验教训 38 / 测试结果 28 / 结果判定 10。

## §6 四列协作关系（追溯定位）

- **「条款」**：原条款号（最权威的来源定位）；
- **「用例编号」**：产品代码-测试模块代码-流水号（归属信息）；
- **「关键词」**：标准专有名词（便于检索）；
- **「条款要求」**：实质要求描述（不出现条款号/原文）。
