# 覆盖自检清单（V3.0）

本文件是 `SKILL.md` 第七步第六「自检」的自检表。

> **V3.0 变更**：新增 §3A「步骤展开与预期结果分条自检」（响应 V3.0 三项针对性优化）；其余保持框架不变。
>
> **V2.0 变更**：新增 §0 四形态覆盖自检（针对 V1.0 系统性漏项）、§1A 验证方式标签分布、§5 条款号存在性与连续性自检、§6 引用标准版本自检；其余保持「只核对条款是否被忠实完整转化，不做条款外强制覆盖」的原则。
>
> **基础原则（不变）**：自检只核对"条款是否被忠实、完整地转化为用例"，不做条款外场景的强制覆盖——条款未规定的联锁场景、性能测试点等不得为凑覆盖而生成用例；产品侧确有需要的，仅以【产品场景提示】写入「经验教训」列。

## §0 四形态覆盖自检（V2.0 新增，最先执行）

> 实证背景：对 YY 9706.262-2021，V1.0 生成 15 条而人工参考版 85 条，漏项 100% 集中在 A/C/D 三类。

| 形态 | 自检动作 | 不通过时的处理 |
|------|----------|----------------|
| **A 章级兜底** | 逐章扫描标准正文，凡出现「除下述内容外，通用标准第 X 章适用」是否已成 1 条？ | 补生成 A 类条，关键词首位 `引用` |
| **B 条款本体** | 带限值/可观察判据的条款是否已拆解？ | 按 `clause-splitting-rules.md` 补拆 |
| **C 文档/记录审查** | 凡出现「技术说明书应…」「用户手册应…」「应形成风险管理文档」是否已成条？条款明示的清单项是否按粒度拆全？ | 补生成 C 类条 |
| **D 引用标准展开** | `expand_refs=on` 时，「按某标准第 X 章」是否已展开子项并标注【限值来源】？ | 补展开或改为指向性条 + 【需人工复核】 |

**豁免记录**：确实无法成条的条款，必须在交付说明中逐条列出并写明理由，不得静默丢弃。

## §1 测试模块覆盖统计（信息性，非强制）

按测试模块统计用例数，如实呈现分布：

| 测试模块 | 用例数 |
|----------|--------|
| AP 外观 / ST 结构 / HW 硬件 / SW 软件 | |
| PF 性能 / RL 可靠性 | |
| GR 安规-通标 / PR 安规-专标 | |
| FT 功能 / ESD EMC（静电）/ EMC EMC | |

> 某模块为 0 条时，只需说明原因（标准未规定该模块条款），**不得为填满模块而编造条款外用例**。

## §1A 验证方式标签分布（V2.0 新增）

按 SKILL §九 的 6 个标签统计：`实测 / 目击检查 / 文档审查 / 风险文档审查 / 软件资料审查 / 引用`。

> 若「引用」为 0，说明 A 类章级兜底全部漏项 → 回到 §0 复核。

## §2 输出顺序自检

1. **按标准条款顺序排列**：以条款号升序为主键；
2. **同条款内按拆分序号排列**：`[单元 1/N]`…`[单元 N/N]`；
3. **禁止按分类重新排序**；
4. **禁止合并同类项**：不同条款的用例不得合并为一条概括用例。

## §3 红线符合性自检（逐条核对）

1. 每条用例是否都能追溯到具体正文条款号？（无条款来源的用例 → 删除）
2. 每条用例的环境条件、前置条件、限值、判据是否都能在条款原文**或其规范性引用文件**找到出处？（含实验室惯例/产品规范 → 移出判定列，改为【产品场景提示】）
3. **引用展开获得的限值是否在「经验教训」列标注【限值来源】**？（未标注 → 补标）
4. 是否存在条款未规定、为覆盖产品场景而生成的用例？（→ 删除，需要时改为【产品场景提示】）
5. 是否存在把同一次物理试验拆成多条的情况？→ 合并
6. 是否存在判定对象为试验装置/环境的用例？→ 降级为前置条件
7. **C 类文档/记录审查用例的预期结果是否可判定**？（写成"文档齐全""满足要求"的 → 改写为条目清单式判据）
8. **「前置条件」是否存在留空或填 `/`**？（→ 补全）
9. **「关键词」首位是否为合法的验证方式标签**？（缺失或自造 → 修正）

## §3A 步骤展开与预期结果自检（V3.0 新增）

逐条核对：

| # | 自检项 | 不通过处理 |
|---|--------|-----------|
| 1 | **预期结果是否分条**（`1) 2) 3)`）？ | 多判据揉成一段 → 按 §四步 4.2 拆条 |
| 2 | **单条是否 ≤60 字**？ | 超限说明判据混装 → 继续拆 |
| 3 | 是否残留 `符合要求即通过`/`各项均满足标准规定`/`无异常` 式收尾？ | 删除收尾语，判据本身已含合格边界 |
| 4 | **测试步骤中是否残留 `按 <标准号> 执行/测量` 式指向语**？ | 命中且方法在 `test-method-toolkit.md` → **展开为操作序列**；库外 → 保留并标【需人工复核】 |
| 5 | 展开后的步骤是否代入**本条具体参数**，而非照抄工具库示例数值？ | 代入条款原文参数；工具库数值仅占位 |
| 6 | **步骤参数是否完备**（设备/连接、量值允差、时长、工况、观察记录、安全防护）？ | 对照 `clause-splitting-rules.md` §2.8 的 7 类信息表回补条款已写明项 |
| 7 | 是否存在"测量 XX 并比较"式**无参数步骤**？ | 升级为含量值/次数/数据点的可照做步骤 |

> 红线：路径 B（库外方法）未标【需人工复核】= 违规；路径 A 步骤中仍出现标准号 = 违规。

## §4 分类归属自检（举例）

- GB 9706.1 漏电流/接地/耐压 → `CM-GR`（或项目主类别-GR）
- YY 9706.102 / GB 4824 系列 → `<主类别>-EMC`
- GB/T 17626.2 静电放电 → `<主类别>-ESD`
- 产品专用安全标准条款 → `<主类别>-PR`
- 使用说明书/标识要求 → `AP`
- 技术说明书的准确性与不确定度 → `AP`
- 风险管理文档审查 → `SW` 或 `PR`（视条款所属章节）
- 软件资料 / PEMS → `SW`
- 报警、联锁（条款明确规定的场景）→ `FT`

> 联锁类用例只覆盖**条款明确规定的场景**；产品侧补充场景（断电复电、误操作旁路等）不成条，仅在有对应条款用例的行内以【产品场景提示】备注。

## §5 条款号存在性与连续性自检（V2.0 新增）

1. 每条用例的 `clause_ref` 是否都在 `_meta.clause_index`（从标准正文提取的条款清单）中？
   - 不在 → **报错**（典型笔误：`201.1` 误写为 `201.10`）；
2. 相对标准条款清单是否存在**跳号 / 跳章**？（如标准有 201.8 但无用例且无豁免说明）
3. 扫描版 OCR 水印遮挡导致条款缺失的，是否在【需人工复核】中标注？

> 以上由 `scripts/generate_test_cases_excel.py` 自动执行；`clause_index` 缺失时降级为仅格式校验并**告警**。

## §6 引用标准版本自检（V2.0 新增）

按 `references/normative-ref-version-map.md` 核对：

1. 用例中是否存在旧版引用（如 `YY 0505`）→ 替换为 `YY 9706.102-2021`；
2. 用户明确要求沿用旧版的，是否在「经验教训」列注明；
3. 引用的标准号是否完整（含年号）。

## §7 人工复核项自检

1. 复核项是否均使用强制格式：`【需人工复核：<事项> | 来源：<来源>】`？
2. 是否存在无来源的"待确认""待定""TBD"？
3. 复核项是否精准到具体单元行，而非整批标注？
4. 「条款要求」「前置条件」「测试步骤」「预期结果」4 列是否完全不含"待定/TBD"及任何产品场景内容？

## §8 自检输出

